# Шлюз на этом Mac

Этап 10 плана интеграции: шлюз работает постоянно, на этом Mac
(решение 7). Колонка ходит только сюда, поэтому Mac должен быть доступен по одному и тому же адресу и не
спать.

## Служба launchd

`install.sh` собирает шлюз — программу `duowave` на Rust с пультом внутри ([gateway/](../../gateway/README.md)) —
и ставит его, распознавание (GigaAM) и, если в `.env` задан `TTS_OWN_URL`, свой голос (`tts-server`, порт 8091)
системными службами:

- запуск при загрузке Mac, без входа в систему (`/Library/LaunchDaemons`, от имени владельца проекта);
- перезапуск, если процесс завершился (`KeepAlive`, не чаще раза в 10 с);
- Mac не засыпает, пока работает шлюз (`caffeinate -is`: нет сна по бездействию и, от сети, системного);
- шлюз работает в папке проекта, настройки — только из `.env` в ней (режим, порт, ключи), пути из `.env`
  (`data/…`, `content`) — от неё же; в строке запуска переменных нет;
- программа службы — копия сборки в `target/service/duowave`: новые сборки в `target/` до службы не доходят,
  пока `install.sh` не запущен снова;
- журнал — `logs/duowave.log`, прошлые запуски — `.1`…`.5`; распознавание — `logs/asr.log`, голос — `logs/tts.log`.
  Журналы прежнего шлюза на Node (`logs/gateway.log*`) остаются как были.

```bash
pnpm install                    # один раз: зависимости пульта
deploy/macos/install.sh         # собирает пульт и шлюз, ставит службы; sudo спросит сам
deploy/macos/install.sh gateway # только шлюз
deploy/macos/uninstall.sh       # убрать службы
```

Сборка внутри — `pnpm --filter panel build` и `cargo build -p duowave --release`, на Apple Silicon с
`--features silero` (Silero VAD; на Intel конец фразы слышен по громкости); нужен Rust ([rustup.rs](https://rustup.rs)).
Готовая программа вместо сборки — `DUOWAVE=<путь к duowave> deploy/macos/install.sh` (например, `duowave-darwin-*`
из выпуска). Запускать от своего имени, не через `sudo`.

Шлюз, запущенный вручную (например, в терминале), перед установкой остановить: порт один.

- **Проверить:** `target/service/duowave health` в папке проекта (код 0 — `/health` отвечает),
  `sudo launchctl print system/app.duowave.gateway | head`, `tail -f logs/duowave.log`.
- **Обновить из исходников:** `git pull && deploy/macos/install.sh` — соберёт и перезапустит.
- **Обновить из пульта** («Дом» → «Обновления»), если сборка знает ленту выпусков (`UPDATE_FEED_URL`): программа
  заменяется в `target/service`, прежняя остаётся рядом как `duowave.previous`. Вернуть прежнюю:
  `mv target/service/duowave.previous target/service/duowave` и
  `sudo launchctl kickstart -k system/app.duowave.gateway`.

## Что ещё сделать руками

- **Постоянный адрес Mac** — резервирование DHCP в роутере на MAC-адрес Mac. Колонка знает только адрес
  из своего конфига.
- **Только домашний Wi-Fi** — у остальных известных сетей снять «Подключаться автоматически» (Системные
  настройки → Wi-Fi → Известные сети → «…»): иначе при пропадании домашней сети Mac уйдёт в другую и сам не
  вернётся, колонка останется без голоса. Колонка находит шлюз только в домашней сети.
- **Mac нужен и в другой сети** — в домашнюю его подключить кабелем (USB-LAN) с тем же постоянным адресом, а
  Wi-Fi оставить другой сети: колонка дойдёт до шлюза по кабелю.
- **Ноутбук с закрытой крышкой** засыпает и с `caffeinate`, если к нему не подключены питание и внешний
  монитор: держать открытым или настроить энергосбережение.
- **Если Mac недоступен** — у колонки нет голоса ни в одном режиме; вернуть её к Яндексу:
  `scripts/station-voice.sh yandex` (README, «Вернуть колонку к Яндексу и обратно»).

## Безопасность и рост данных

- Порт 80 и отладочный API — только в доверенной сети: отладочный API отвечает только адресам из
  `DEBUG_API_ALLOW` (по умолчанию — домашние сети и localhost), `DEBUG_API_ENABLED=false` выключает его.
- Секреты (ключ Claude, токены Home Assistant и Telegram, пароли Asterisk) — только в `.env`.
- Журналы и звук растут на ~20 МБ в день: `RECORDER_RETENTION_DAYS` хранит столько дней.
- Колонка не подключена дольше `STATION_OFFLINE_ALERT_MIN` минут — запись в журнал, уведомление macOS,
  `ALERT_WEBHOOK_URL`, `ALERT_TELEGRAM_CHAT`.

Отдельная машина вместо Mac — служба systemd ([deploy/linux/](../linux/README.md)) или Docker (`compose.yaml` в
корне).
