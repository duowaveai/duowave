# LiveKit для своих звонков

Необязательный переходник звонков, как SIP: ядро — WebRTC через наш узел (`/calls`), а LiveKit нужен,
когда звонки выходят за пределы дома, появляются мобильные приложения или разговор на несколько человек.

## Как устроено

- Шлюз входит в комнату семьи (`LIVEKIT_ROOM`, по умолчанию `home`) участником «Колонка» и публикует
  голос колонки, пока идёт звонок.
- Каждый другой участник комнаты — сторона нашего узла: «Алиса, позвони маме» звонит маме, если она в
  комнате; её звонок колонке объявляется голосом Алисы, «Алиса, ответь» соединяет.
- Сигналы звонка — сообщения данных комнаты с темой `duowave`: `call`, `accept`, `hangup` от участника;
  `incoming`, `ringing`, `connected`, `ended` к нему.
- Комната одна на семью: звонок — один на один по договорённости, голос колонки слышат все участники комнаты.

## Сервер

- **Свой** (`docker-compose.yml`, образ `livekit/livekit-server:v1.13.10`): скопировать
  `livekit.yaml.example` в `livekit.yaml`, задать ключ и секрет, `docker compose up -d`. Дома — только в
  домашней сети. Для звонков снаружи — на машине с публичным адресом и доменом с TLS: браузеры дают
  микрофон только по HTTPS.
- **Docker Desktop на Mac:** сервер в контейнере сообщает клиентам адрес контейнера, и звук до него не доходит.
  В `livekit.yaml` — `rtc.node_ip`: `127.0.0.1`, если страница открыта на этом же Mac (проверено 02.11), или
  адрес Mac в домашней сети для телефонов дома.
- **LiveKit Cloud** — URL, ключ и секрет проекта, без своего сервера; звук звонков идёт через их облако.

В пульте шлюза, «Дом» → «Коннекторы» → LiveKit: адрес для шлюза (`ws://…:7880` или `wss://…`), API-ключ и
секрет из `livekit.yaml`, комната; «Проверить» спросит сервер, сколько в нём комнат. Перемены — сразу, без
перезапуска шлюза. Переменные `LIVEKIT_*` в `.env` шлюз читает только при первом запуске.

## Снаружи дома

Звонкам снаружи нужны HTTPS для страницы звонка (браузер даёт микрофон только так) и путь для звука WebRTC по UDP.
Как это устроить, зависит от вашей сети, и здесь это не описано. Шлюз считает внешним всё, что пришло не из
домашней сети: отладка, выдача доступов, сокеты колонки и звонков снаружи закрыты.

## Участники

- Страница `/calls/livekit`: дома кнопка «Получить доступ» выдаёт токен на месяц и сохраняет его в
  браузере. Токены выдаются только в домашней сети, дальше страница работает и снаружи, если сервер
  LiveKit доступен.
- Токен из командной строки, в домашней сети: `curl -G --data-urlencode 'name=Мама' http://<шлюз>/calls/livekit/token`
  — на месяц, как у кнопки. На компьютере шлюза — и без запущенного шлюза: `duowave livekit-token --name "Мама"
  [--days 30]` (те же `LIVEKIT_*` из `.env`; печатает тот же JSON `{"url","token"}`).
- Мобильные приложения — на SDK LiveKit: войти с токеном и слать те же сообщения данных.
