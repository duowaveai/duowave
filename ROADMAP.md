# Дорожная карта: открытый шлюз, сообщество и облако

Статус: предложение, решения владельца ниже ещё не приняты. Составлено 04.11.2026 по вики
[hackalice.me](https://hackalice.me) и соседним проектам. Что шлюз умеет сейчас — в
руководстве и в плане «Алиса без Яндекса»; кто
пользуется пультом — в [PRODUCT.md](PRODUCT.md).

## Суть

- Шлюз — открытый проект поверх работы сообщества hackalice. Root и доступ к колонке — у сообщества;
  шлюз, пульт и подключения — здесь. Свой способ взлома не делаем.
- Своя установка остаётся бесплатной и полной. Облако появится позже как платное удобство: не держать
  компьютер включённым, не заводить свои ключи, открывать пульт вне дома.
- Образец — Home Assistant и Nabu Casa: открытое ядро работает у себя, подписка оплачивает удобство
  и разработку.

## Принципы

1. **Взлом — у сообщества.** Шлюз — сервер со своим протоколом. Подключение колонки — маленький
   обратимый шаг после root по вики; сам root шлюз не делает и не распространяет.
2. **Своё у себя — полное.** Облако не отнимает у своей установки ни одной возможности.
3. **Стандарты вместо своих форматов:** MCP — для инструментов, OpenAI-совместимый API — для моделей,
   Wyoming — для распознавания и синтеза и для связи с Home Assistant.
4. **Свой код:** чужие проекты изучаем, но не переносим.
5. **Про деньги — честно с первого дня:** сообщество узнаёт о будущем облаке до первого поста о шлюзе.
6. **Без идентификаторов** в коде, истории, журналах и примерах: ID колонки, токены, chat id, имена
   из звонков, записи голоса, координаты. Правила вики о публикации совпадают с нашими.

  Предложение: «MIT OR Apache-2.0» — SDK исполнителей, библиотека протокола и всё для колонки. Подробно — в плане открытия.
  Тексты — в `docs/open-source/` (06.11): при выпуске `scripts/release/snapshot.sh` кладёт их в корень.
- **Проверка истории перед открытием:** сканер секретов и ручной просмотр журналов, тестов, `docs/`

- **README для посторонних:** что это, чем отличается от мостов, как поставить, как откатить. Рядом —

- **Критерий:** человек из чата по README понимает, что это и чем он рискует, ещё до установки.

### Этап 1. Шлюз, который ставит посторонний

Большая часть возможностей уже есть: разговор, своё распознавание и синтез, таймеры, погода, звонки,
плеер (таблица на 03.11 — в плане без Яндекса). Но поставить шлюз
сейчас может только владелец: Mac, `.env` и несколько служб вручную.

- **Установка одной командой:** Docker Compose или установщик. Два набора:
  - лёгкий — распознавание и синтез через OpenAI-совместимые сервисы, без видеокарты;
  - полный — свои GigaAM и Silero рядом.

  Сделано 06.11: `compose.yaml` (наборы `full` и `gpu`, звонки — `compose.calls.yaml`), служба systemd, дополнение
  для Home Assistant, приложение на Tauri (проверено на Mac); образы собраны и запущены на Mac. В тот же день всё это
  переведено на шлюз на Rust — одну программу `duowave` с пультом внутри (план): образ —
  статическая программа на Alpine, приложение — со шлюзом внутри, без Node; приложение в таком виде ещё не запускали
  ([desktop/README.md](desktop/README.md), «Что проверено»).
- **Подключение колонки:** мастер в пульте, команда для колонки, позже пакет для `yse` — копия `quasar.cfg`,
  адрес шлюза, откат одной кнопкой. Работает после root по вики. Экраны мастера, сборки под Linux, Windows и
  Docker, приложение и что может жить на самой колонке — в плане открытия. Сделано 06.11:
  мастер, «Сделаю сам» и пакет `duowave` для `yse`; подключение проверено на колонке владельца.
- **Первый пульт в «Стекле»** ([DESIGN.md](DESIGN.md)): колонка, режим, маршруты, журнал. Настройки
  меняются без правки `.env` и перезапуска.
- **Где запускать:** Mac, Raspberry Pi, NAS или домашний сервер.
- **Вторая модель колонки** — с помощью сообщества: сейчас всё проверено только на Лайт 2.
- **Критерий:** человек из чата ставит шлюз за вечер и возвращает колонку как было одной командой.

### Этап 2. Подключения

- **SDK исполнителей** (MIT): возможность → исполнитель. Формат лучше согласовать с Quasar Bridge.
- **MCP:** любые MCP-серверы — инструменты модели; Home Assistant — тоже через MCP. Сделано 06.11:
  серверы и провайдеры моделей из пульта, доверие по отпечаткам, вход через OAuth (README, «Мозг и подключения»).
- **Агенты** (Hermes, OpenClaw) — исполнители разговора и действий, с правами, которые задаёт админ.
- **Wyoming:** распознавание и синтез из мира Home Assistant; интеграция для самого Home Assistant —
  путь к его пользователям.
- **Связь:** звонки и Telegram уже есть — в общий каталог; другие мессенджеры — подключениями.
- **Каталог подключений в пульте** — экран «Подключения» из макетов.
- **Критерий:** участник сообщества добавляет своё подключение, не меняя ядро шлюза.

### Плагины и темы (сквозное, к этапам 2–4)

Темы пульта с разными раскладками и плагины шлюза: голосовые навыки, инструменты «Мозга», музыка и радио,
подключения к API, вкладки пульта; агент пишет плагин в сессии; каталог. На колонке — бюджет памяти и его показ в
пульте. План. Сделано 07.11.2026, этапы 1–10: темы и оболочка пульта («Стекло» и «Простор»),
плагин-хост с Host API 1.1, бюджет памяти колонки, экран пакетов и плагины пульта на ходу, ответы колонки в журнал и
плагину с запасным путём звука через шлюз, мастерская (пульт, голос, MCP, `duowave plugin`), «колонка + сервер»,
подписанный каталог, движки WASM и MCP, приложения отдельным процессом, встроенные навыки — встроенными плагинами.
Осталось руками владельца: проверка вживую на колонке, замер запаса памяти и перекодирования, проверка аккаунта
Spotify (решения 2, 3, 5, 6).

### Этап 3. Семья

- Профили, роли (админ, домашние, гости) и правила админа — как в [PRODUCT.md](PRODUCT.md).
- Узнавание по обращению; по голосу — только дома, на сервер голос не отправляем: это биометрия,
  закон охраняет её строже прочих данных.
- **Критерий:** у каждого домашнего своё управление, гость не выходит за рамки, заданные админом.

### Этап 4. Облако

**4а. Удобства без голоса.** Пульт с телефона вне дома без проброса портов, копия настроек,
уведомления. Голос и запросы через облако не идут.

**4б. Облачный шлюз** — чтобы не держать компьютер включённым:

- **Связь с Яндексом остаётся дома.** Голос Алисы сейчас идёт через сессию, открытую учётными данными
  колонки. Облако с такими сессиями тысяч колонок — это чужие учётные данные у нас, риск блокировки
  наших адресов и претензии Яндекса. Поэтому эта часть живёт на самой колонке или в маленьком
  домашнем шлюзе, а в облако уходят только запросы к своим исполнителям.
- **Часть на колонке.** Quasar Bridge работает на самой колонке своим установщиком (от YAM ушёл в v0.5.0; проверяется в эмуляторе КУЯСЭ на Станции 2 и Мини).
  На чём писать — решено 06.11: на Rust. Та же программа `duowave`, собранная для колонки
  (`--no-default-features --features station`, статическая aarch64 musl, 4,5 МБ), собрана и упакована для `yse`
  (`station-client/yap/`); в контейнере linux/arm64 она держит 3 МБ памяти (каркас). Хватит ли ресурсов Лайт 2 —
  проверить на самой колонке: этот шаг отложен владельцем (план, этап 5).
- **Модели в подписке** — только те, что можно законно продавать пользователям из России: YandexGPT,
  GigaChat, открытые модели на своих или арендованных серверах в России. OpenAI и Anthropic Россию
  не обслуживают. Свой ключ к любому OpenAI-совместимому сервису — в своей установке, как сейчас.
- **Персональные данные:** с облаком для пользователей из России мы — оператор по 152-ФЗ: данные
  хранятся в России, нужны политика конфиденциальности и согласия. Записи голоса по умолчанию
  не храним.
- **Юридически:** ИП или ООО, оферта; консультация юриста — до первого платного пользователя.
- **Сообществу:** часть подписки — вики и авторам способов root (решение владельца).
- **Критерий 4а:** пульт открывается вне дома без настройки роутера. **4б:** колонка работает, когда
  компьютер дома выключен.

## Как заходим в сообщество

1. **Сначала показать.** Публичный репозиторий, README и короткое видео: колонка отвечает голосом
   Алисы, на вопрос ответил свой исполнитель, пульт показывает, кто именно.
2. **Личное сообщение автору вики** ([Marker284](https://github.com/Marker284)) до поста в чате: что
   делаем, за что не берёмся (взлом), что предлагаем (рецепт, пакет, общую библиотеку протокола)
   и честно — про будущее облако.
3. **Разговор с автором Quasar Bridge:** общий формат маршрутов и настроек MCP, возможно — общая часть
   на колонке.
4. **Вклад раньше рекламы.** Находки о голосовом тракте — `TtsGenerate` по фразам, `SynchronizeState`,
   поведение после `NO_SPEECH` — в `docs/internals/voice.md` вики, без идентификаторов, по её
   [CONTRIBUTING](https://github.com/Marker284/yandex-station-extended/blob/main/CONTRIBUTING.md).
5. **PR в рецепт** [«Своя LLM вместо Алисы»](https://hackalice.me/recipes/llm/): столбец в таблице
   сравнения и раздел про шлюз.
6. **Пост в [@hackalice](https://t.me/hackalice)** — когда первые пять пунктов сделаны.

## Риски

- **Яндекс закрывает способы root или меняет протокол.** Протокол шлюза открыт и для других устройств:
  колонки на ESP32, Home Assistant Voice, телефон. Станция — первое устройство, но не единственное.
- **Претензии к платному сервису.** Держимся в стороне от взлома, не используем знаки Яндекса и Алисы,
  не держим чужие учётные данные в облаке.
- **Сообщество примет облако за наживу.** Честность с первого дня, полная своя установка, доля
  сообществу.
- **Тяжёлая установка:** сейчас это несколько служб. Лёгкий набор на облачных сервисах — с первого
  публичного выпуска.
- **Один человек на проекте.** Со временем — второй мейнтейнер с правом выпускать версии.
- **Голос и персональные данные.** Не храним по умолчанию, узнавание голоса — только дома.
