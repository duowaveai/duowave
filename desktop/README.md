# Приложение DuoWave

Шлюз для компьютера без командной строки: приложение для Windows, macOS и Linux ставит шлюз, запускает его,
держит значок в трее и показывает пульт в своём окне. Внутри — шлюз на Rust (крейт `duowave`, `../gateway`), тот
же, что программа `duowave`: оболочка на Tauri v2 собирается вместе с ним и запускает его в своём же процессе.
Ни Node, ни второго процесса нет.

## Как устроено

- `src-tauri/` — оболочка на Rust. При старте она пишет первый `.env` в папку данных (`PORT=7780`: на этот порт
  ходит колонка, адрес с портом шлюз сам записывает ей при подключении), запускает шлюз (`src/engine.rs`) с `DATA_DIR=<папка данных>` и открывает пульт
  `http://127.0.0.1:<PORT>/panel`, как только шлюз слушает порт. PORT приложение только читает: шлюз берёт его из
  `.env` сам. `GET /health` раз в несколько секунд говорит, отвечает ли шлюз и на связи ли колонка.
- Пульт вшит в шлюз при сборке (`gateway/build.rs` и rust-embed берут `panel/dist`): `cargo tauri build` сначала
  собирает пульт (`beforeBuildCommand`: `pnpm --filter panel build` в корне репозитория).
- `src/` — заставка, пока шлюз запускается, и объяснение, если он не смог: порт занят (другой программой или уже
  работающим шлюзом) — тогда кнопка «Взять свободный порт»: приложение находит свободный (с 7780 и дальше), пишет его
  в `.env` и запускает шлюз на нём, а колонку, подключённую к прежнему порту, пульт предлагает переподключить; нет
  прав на порт, ошибка в `.env`, шлюз не запустился за 90 секунд.

Меню значка: «Открыть пульт»; строка состояния (шлюз работает · колонка на связи / запускается / не отвечает /
остановлен); «Перезапустить шлюз»; «Запускать при входе»; «Не давать компьютеру засыпать»; «Папка с данными»;
«Журнал»; «Выход». Закрытое окно прячется, шлюз продолжает работать. Второй запуск приложения открывает пульт
первого. При входе в систему (`--autostart`) приложение стартует без окна.

При выходе шлюз останавливается мягко: закрывает соединения, журнал запросов и базу; если за 6 секунд не успел —
заканчивается вместе с приложением. Так же — по Cmd+Q, `kill` и концу сеанса Linux. Шлюз и приложение — один
процесс, поэтому упавшее приложение шлюза за собой не оставляет. Шлюз, остановившийся сам после 30 секунд
нормальной работы, приложение запускает снова; остановившийся раньше — нет, тогда оно показывает причину.

Окружение шлюза — только системное (PATH, HOME, прокси, сертификаты, переменные моделей) и `DATA_DIR`:
настройки шлюза берутся из `.env` папки данных, а не из оболочки, откуда запустили приложение. Куда что
класть внутри папки данных, решает сам шлюз. Программы, которые шлюз запускает (свои серверы моделей, голосовая
лаборатория), получают `DATA_DIR` и переменные моделей из `.env` папки данных: приложение ставит `DATA_DIR` и
`DUOWAVE_MANAGED=desktop` в своё окружение до старта.

### Что лежит рядом с программой

Рабочая папка шлюза — ресурсы приложения (`Contents/Resources` в .app, папка программы в Windows и Linux): там
`clone-server/` — код сервера своих голосов для голосовой лаборатории (`server.py`, `imprint.py`, `voicelab/`,
`requirements/`), без `runtime/`: движки ставятся на каждый компьютер в папку данных. Миграции базы, пульт и
поставляемый контент (`radio.json`, `README.md` для `content/`) вшиты в программу.

Сборка приложения — с возможностями шлюза по умолчанию (`pc`): подключение колонки по SSH, свои серверы моделей,
голосовая лаборатория. Без `silero` (конец фразы шлюз слышит по энергии) и без звонков (`livekit`, `webrtc`):
им нужны готовые библиотеки, которые скачиваются при сборке.

## Где данные и журнал

| | Данные (`DATA_DIR`, там же `.env`) | Журнал шлюза |
|---|---|---|
| macOS | `~/Library/Application Support/app.duowave.desktop/` | `~/Library/Logs/app.duowave.desktop/gateway.log` |
| Windows | `%APPDATA%\app.duowave.desktop\` | `%LOCALAPPDATA%\app.duowave.desktop\logs\gateway.log` |
| Linux | `~/.local/share/app.duowave.desktop/` | `~/.local/share/app.duowave.desktop/logs/gateway.log` |

В папке данных — всё, что пишет шлюз: база и её ключ (`state/`), журналы сессий, контент, голоса, лаборатория
своего голоса, журналы моделей. Там же `desktop.json` (настройки приложения). В `gateway.log` — журнал шлюза и
строки самого приложения с пометкой `[app …]`; больше 10 МБ — при запуске приложения прошлый уходит в
`gateway.log.1`. Удаление приложения папку данных не трогает.

`DUOWAVE_DATA_DIR=<папка>` при запуске приложения заменяет папку данных, журнал тогда пишется в её `logs/`. Это
для проверок и переносной копии.

## Сборка

Всем системам нужны Rust (rustup) и Tauri CLI, для пульта — Node 26 и pnpm 11:

```sh
cargo install tauri-cli --version "^2" --locked
pnpm install                                   # в корне репозитория: vite для пульта берётся оттуда
cd desktop/src-tauri
cargo tauri build                              # пульт, затем приложение и все установщики своей системы
```

Каждую платформу собирают на ней самой (в CI — на своём раннере).

### macOS

- Xcode Command Line Tools.
- `cargo tauri build --bundles app` — `target/release/bundle/macos/DuoWave.app`, `--bundles dmg` — образ.

### Windows

- Visual Studio Build Tools (C++), WebView2 (есть в Windows 10 и 11).
- Установщики: NSIS (`target/release/bundle/nsis/`, ставится в профиль пользователя, без прав администратора) и
  MSI (`bundle/msi/`, на весь компьютер).
- Порт бывает занят другой программой: приложение скажет и предложит свободный.
- При первом запуске Windows спросит про брандмауэр: шлюзу нужна частная сеть, иначе колонка его не найдёт.

### Linux

- Пакеты для Tauri, для Debian и Ubuntu:
  `sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev`.
- Установщики: deb, rpm, AppImage.
- Порты ниже 1024 (например, 80, если его задали в `.env`) на Linux открывает только root. Приложение, не открыв
  порт, покажет команду: для deb и rpm —
  `sudo setcap cap_net_bind_service=+ep <программа приложения>` (путь — в подсказке, обычно
  `/usr/bin/duowave-desktop`). Для AppImage (setcap внутри образа не работает) — всем программам:
  `sudo sysctl -w net.ipv4.ip_unprivileged_port_start=80`, навсегда — та же настройка строкой в `/etc/sysctl.d/`.
- Значок в трее — через AppIndicator; в GNOME нужно расширение AppIndicator.

### В CI

`release.yml`, задача `desktop`: матрица `macos-15` (arm64), `macos-15-intel` (x64), `windows-latest`,
`ubuntu-22.04` (x64), `ubuntu-24.04-arm` (arm64). Node и pnpm там только для пульта; собирает и выкладывает
установщики `tauri-apps/tauri-action`. Зависимости Rust выпуск берёт из кэша, который раз в сутки греет
`warm-cache.yml` на `main` (прогон по тегу видит только кэш своего тега и `main`). `ci.yml`, задача `desktop`:
`cargo fmt`, `cargo clippy` и `cargo test` приложения на Linux.

## Подпись

Без подписи приложение работает, но система пугает при установке.

- **macOS.** Apple Developer Program — $99 в год, сертификат Developer ID Application, затем нотаризация. Без них
  Gatekeeper пишет, что разработчика не удалось проверить; открыть можно в «Системные настройки →
  Конфиденциальность и безопасность» → «Всё равно открыть» (на macOS 15 правая кнопка → «Открыть» уже не
  помогает). Без сертификата бандл подписывается ad-hoc целиком (`bundle.macOS.signingIdentity: "-"`): иначе
  подписан только сам файл программы, ресурсы — нет, и скачанное приложение macOS называет «повреждённым» без
  кнопки «Всё равно открыть» (так было в 0.1.0). Tauri подписывает по-настоящему, когда заданы
  `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY`, и нотаризует с `APPLE_ID`,
  `APPLE_PASSWORD`, `APPLE_TEAM_ID`. Исполняемый файл один — сама программа; она подписывается с
  `entitlements.plist` (микрофон для записи голоса в пульте). В ресурсах исполняемых файлов нет.
- **Windows.** Сертификат подписи кода (OV или EV; с 2023 года ключ — только на токене или в облачном HSM; Azure
  Trusted Signing — недорогой вариант). Без подписи SmartScreen показывает «Система Windows защитила ваш
  компьютер» → «Подробнее» → «Выполнить в любом случае». В Tauri — `bundle.windows.certificateThumbprint` или
  `bundle.windows.signCommand`.
- **Linux.** deb, rpm и AppImage подписи не требуют; репозиторий пакетов подписывают ключом GPG.

## Обновления

`tauri-plugin-updater` подключён, но выключен, пока нет ленты выпусков: в `tauri.conf.json` адрес-заглушка на
`.invalid`, и приложение с таким адресом обновления не проверяет. Включить:

1. Ключ подписи уже создан (06.11.2026, `cargo tauri signer generate`): открытый — в `plugins.updater.pubkey` и в
   `gateway/updates.pub` (им же шлюз на Rust проверяет свои обновления), закрытый — у владельца в
   `~/.tauri/duowave-updates.key`, вне репозитория. Его содержимое — в секрет CI `TAURI_SIGNING_PRIVATE_KEY`,
   `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — пустой. Потеряется ключ — установленные приложения больше не обновятся.
2. `plugins.updater.endpoints` — лента, например
   `https://github.com/<владелец>/<репозиторий>/releases/latest/download/latest.json`; `latest.json` пишет
   tauri-action.
3. `bundle.createUpdaterArtifacts: true` — сборка начнёт подписывать архивы обновлений.

Тогда приложение проверяет ленту через 30 секунд после запуска и потом раз в час. Если есть новое, оно добавляет
в меню «Обновить до X» и один раз на каждую версию показывает уведомление macOS (какую версию уже показало, помнит
файл `update-notified` в папке данных). Шлюз внутри видит ту же ленту и показывает то же предложение в пульте:
точка на «Дом», строка «Доступна версия X» на главном экране, а в «Дом → Шлюз → Обновления» — что нового и
кнопка. Открытый раздел «Обновления» сам спрашивает ленту, если с прошлой проверки прошло больше 10 минут. Его «Обновить» ставит обновление
приложения через тот же `tauri-plugin-updater`. Перед установкой шлюз останавливается, после неё приложение
перезапускается. Обновляются .app (macOS), NSIS и MSI (Windows), AppImage (Linux); deb и rpm — через менеджер
пакетов.

## Не давать компьютеру засыпать

Спящий компьютер оставляет колонку без шлюза. Пока шлюз работает, приложение не даёт системе уснуть, экран
гаснуть может. На macOS — `caffeinate -is -w <pid приложения>` (так шлюз владельца работает и сейчас; `-s`
действует только от сети), на Windows — `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)`, на
Linux — `systemd-inhibit --what=idle:sleep`. Запрет снимается, когда шлюз останавливается, когда приложение
закрывается и когда пункт меню «Не давать компьютеру засыпать» выключен. По умолчанию пункт включён; выбор
хранится в `desktop.json` в папке данных. Закрытая крышка ноутбука без внешнего экрана усыпит его всё равно.

## Разработка

- `cargo tauri dev` в `src-tauri/` собирает пульт (`beforeDevCommand`) и запускает оболочку с заставкой из
  `src/` (сборщика нет). В отладочной сборке шлюз читает пульт из `panel/dist` с диска, а не из программы.
- Чтобы не мешать работающему шлюзу: `DUOWAVE_DATA_DIR=/tmp/duowave-test cargo tauri dev`, а в
  `/tmp/duowave-test/.env` заранее — свободный порт (`PORT=18080`) и `STATION_OFFLINE_ALERT_MIN=0`.
- `cargo test` в `src-tauri/` — первый `.env`, окружение шлюза, проверка `/health`, занятый порт и ошибка в `.env`,
  запуск, ответ и остановка шлюза в процессе, журнал, настройка сна.
- Значки: `cargo tauri icon ../icon.svg` в `src-tauri/` (папки `icons/android` и `icons/ios` удалить), значок
  строки меню: `cargo tauri icon ../tray.svg --png 44 -o /tmp/tray`, затем `/tmp/tray/44x44.png` →
  `icons/tray-template.png`.

## Что проверено

С шлюзом на Rust внутри, на macOS (Apple Silicon): приложение собирается (`cargo build`), `cargo clippy` чист,
тесты проходят; тест, который запускает шлюз в процессе приложения, проверяет CI.

06.11 приложение (сборка `cargo build`) запущено со своей папкой данных (`DUOWAVE_DATA_DIR`): шлюз внутри
поднялся за 2 с, `/health` — `ok` с возможностями ПК, пульт отдаётся; занятый порт приложение назвало в журнале
(«порт 8098 занят»), а не упало. Обновление шлюза проверено целиком на временном ключе: лента → «Доступна версия» →
установка из API пульта → подпись проверена, программа заменена, прежняя — `duowave.previous`, перезапуск в том же
процессе; откат на `duowave.previous` работает, архив с неверной подписью не ставится. Шлюз собирается для Linux
x86_64 (musl, статический) и Windows x86_64 (windows-gnu, через zig).

Установщик для macOS собирается: `cargo tauri build --bundles app,dmg` — `DuoWave.app` 27 МБ и
`DuoWave_0.1.0_aarch64.dmg` 12 МБ. Обновление самого приложения проверено целиком на временном ключе и
локальной ленте (свой `--config`: версия, `identifier`, `pubkey`, `endpoints`, `dangerousInsecureTransportProtocol`):
версия 0.1.0 запущена, шлюз внутри предложил 0.2.0, установка из API пульта прошла через обновлятор Tauri —
архив скачан, подпись проверена, шлюз остановлен, приложение заменено и перезапущено, новый процесс — 0.2.0, шлюз
снова отвечает через 9 с. Второй экземпляр с тем же `identifier` не запускается (single-instance): для проверки
рядом с установленным приложением нужен свой `identifier`. Установщики для Windows и Linux соберёт CI.
