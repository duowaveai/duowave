# Свой синтез речи

Сервер синтеза с OpenAI-совместимым API: шлюз шлёт фразу в `POST /v1/audio/speech` и получает WAV
(16 бит, моно), а для колонки сам кодирует его в Ogg/Opus. Тот же вызов принимает и OpenAI, так что
вместо этого сервера можно указать любой совместимый.

## Выбор движка

| Движок | Русская речь | Задержка | Где работает | Что учесть |
|---|---|---|---|---|
| Яндекс (голос Алисы) | родной голос колонки, разметка шёпота и звуков | 0,4–1 с до первого звука (замерено) | облако Яндекса, учётные данные колонки | текст ответа уходит Яндексу |
| Silero TTS (`v4_ru`, `v5_ru`) | хорошая, пять голосов: aidar, baya, kseniya, xenia, eugene | 20–100 мс на фразу на Mac M (первая после запуска — 0,7 с), 48 кГц | локально, PyTorch (уже стоит для GigaAM) | модель — CC BY-NC 4.0: только некоммерческое использование, с указанием авторства |
| Piper (`ru_RU`: irina, denis, dmitri, ruslan) | проще, но разборчиво | 20–80 мс на фразу на Mac M, 22 кГц; первая фраза голоса — около секунды | локально, командная строка `piper-tts` (ONNX) отдельным процессом | Piper — GPL-3.0, в процесс сервера не загружается; голоса denis и dmitri — CC0, ruslan — CC BY-NC-SA 4.0, у irina лицензия не указана |
| OpenAI (`/audio/speech`) | хорошая | сеть плюс синтез | облако, платно | текст уходит OpenAI |

Предложение: Silero — основной свой голос (качество, локально), Piper — если важна скорость. В шлюзе свой
синтез — жёсткий выбор `TTS_PROVIDER`: `mixed` — своим голосом наши ответы, `own` — и ответы Яндекса; запасного
перехода с одного голоса на другой нет.

## Запуск

Сервер сам ничего не качает: голоса скачивает шлюз из пульта или кладут руками.

```bash
# Модели — в models/, сервер берёт все сразу:
#   Silero: models/silero/v4_ru.pt — с models.silero.ai/models/tts/ru/v4_ru.pt;
#   Piper: голос — .onnx и .onnx.json рядом, например models/piper-denis/ с huggingface.co/rhasspy/piper-voices
#   (ru/ru_RU/denis/medium). Сам Piper — командная строка piper-tts в своём окружении (готовая сборка
#   2023.11.14-2 для macOS не запускается: в архиве arm64 программа для Intel без своих библиотек).
python3.12 -m venv .venv-piper && .venv-piper/bin/pip install -r requirements-piper.txt

# Один сервер на всё: Python asr-server (torch уже есть); Piper он находит в .venv-piper
../asr-server/.venv/bin/python server.py --port 8091

# Проверка без модели: тон вместо речи
python3 server.py --engine tone --port 8091
```

- **Piper — только отдельным процессом.** Сервер не импортирует его: запускает его командную строку,
  по процессу на голос, и держит её между фразами — голос загружается один раз (~1 с), дальше фраза
  занимает десятки миллисекунд. Таких процессов не больше `--piper-workers` (`PIPER_WORKERS`, по
  умолчанию 2, до ~200 МБ каждый); голос, звучавший давнее всех, отдаёт свой первым. `0` — процесс на
  каждую фразу. Где Piper: `--piper` / `PIPER_BIN`, иначе `.venv-piper` рядом, иначе `piper` в `PATH`.
- **Путь к окружению Piper — короче ~150 символов:** espeak-ng внутри piper-tts держит путь к своим
  данным в 160 байтах и из папки поглубже не говорит ничего (ошибка про `espeak-ng-data/phontab`).
- **Папка голосов:** `--models`, иначе `TTS_MODELS`, иначе `TTS_MODELS_DIR` (та же, куда качает шлюз),
  иначе `$DATA_DIR/voices` при `DATA_DIR`, иначе `models/` рядом с сервером.
- **Новые голоса — без перезапуска.** Скачав голос, шлюз просит `POST /v1/models/rescan`; удалённый так
  же забывается. Голос, положенный руками, заговорит и сам: голос, которого нет, сервер перед ошибкой
  ищет в папке ещё раз. Без голосов сервер тоже стартует — и ждёт их.
- `--host 0.0.0.0` — если шлюз на другой машине; тогда закрыть порт или задать `--api-key`
  (`TTS_API_KEY`, или `TTS_OWN_API_KEY` — то же имя, что у шлюза): всё, кроме `/health`, — только с
  `Authorization: Bearer <ключ>`.

В `.env` шлюза: `TTS_OWN_URL=http://127.0.0.1:8091/v1`, `TTS_OWN_MODEL` — движок (`silero`, `piper`),
`TTS_OWN_VOICE` — голос (`baya`, `xenia`, `denis`…), и `TTS_PROVIDER=mixed` (своим голосом наши ответы) или
`own` (и ответы Яндекса тоже; см. README шлюза). Сменить голос — выбрать его в пульте или поменять эти две
строки и перезапустить шлюз; сервер синтеза не трогаем. Какие голоса есть — `GET /v1/models`.

Шлюз кодирует нашу речь для колонки в Ogg/Opus 48 кГц: в 16 кГц она звучала бы как по телефону.

## API

- `POST /v1/audio/speech` — JSON `{"model", "input", "voice", "response_format": "wav" | "pcm"}`;
- `POST /v1/models/rescan` — перечитать папку голосов: ответ как у `/health` плюс `added` и `removed`
  (файлы голосов). Неизменившиеся голоса остаются загруженными, новый файл Silero сменяет старый;
- `GET /v1/models` — движки и их голоса;
- `GET /health` — движки, голоса, что загружено (`loaded`), сколько фраз озвучено, `features: ["rescan"]`
  (по нему шлюз узнаёт, что голоса можно подхватить без перезапуска) и `errors` — что из папки не взялось.

## Docker

```bash
docker build -t duowave-tts tts-server                                 # Silero и Piper, amd64 и arm64
docker build -t duowave-tts:piper --build-arg SILERO=0 tts-server      # только Piper, без torch
docker run -d --name tts -p 127.0.0.1:8091:8091 -v voices:/models duowave-tts
```

- Слушает `0.0.0.0:8091` внутри контейнера, работает не от root (uid 1000 — как у шлюза: общий том
  голосов принадлежит обоим), проверка здоровья — `/health`.
- `/models` — тот же том, что у шлюза `/data/voices` (так в `compose.yaml`): шлюз качает, сервер
  подхватывает по `rescan`.
- Piper живёт в `/opt/piper`, отдельно от окружения сервера, и запускается только своей командной
  строкой. В образе — код под GPL (piper-tts 1.8.0 с espeak-ng): раздавая образ, давать и ссылку на
  исходники — https://github.com/OHF-voice/piper1-gpl и sdist piper-tts 1.8.0 на PyPI.
- `TORCH=cu126` и другие — Silero на NVIDIA (только amd64); по умолчанию процессор.
- Порт наружу не открывать: в `compose.yaml` шлюз ходит сюда по имени `tts`. Иначе — `TTS_API_KEY`.
