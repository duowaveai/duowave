# clone-server — свой голос: отпечаток и синтез

Панель «Модели → Голос → ＋ Свой голос» снимает **отпечаток голоса** по записям владельца и включает его на колонке.
Обучения нет: модели zero-shot. 5–8 секунд чистой речи и их слова становятся голосом (`voice.pt`), который модель
повторяет на любой фразе. Записи хранятся вместе с голосом — на них можно будет доучить позже.

Три модели. Код у всех Apache-2.0, но веса решают, что можно: у OmniVoice они CC BY-NC 4.0 — дома можно, за деньги
нельзя; у CosyVoice 3 на странице модели написано «только для академических целей»; VoxCPM 2 Apache-2.0 целиком —
код и веса. VoxCPM на видеокарте Мака работает в float32 (в половинной точности глитчится — так решили авторы),
поэтому памяти берёт вдвое больше OmniVoice.

| | OmniVoice (k2-fsa) | CosyVoice 3 (FunAudioLLM) | VoxCPM 2 (OpenBMB) |
|---|---|---|---|
| Мак, Apple Silicon | видеокарта (MPS) | процессор | видеокарта (MPS, float32) |
| Linux + NVIDIA | CUDA | CUDA | CUDA |
| Linux без NVIDIA | процессор, медленно | процессор, медленно | процессор, медленно |
| Windows + NVIDIA | CUDA | нет | CUDA |
| Windows без NVIDIA, Intel-Мак, шлюз в Docker | нет | нет | нет |

Где что можно, шлюз определяет сам: ОС, процессор, ОЗУ, диск, `nvidia-smi`, Docker (`gateway/src/voice_lab/platform.rs`).

## Как устроено

- `runtime/<engine>/` — окружение модели: `env` (свой Python и torch: у моделей разные torch, а в одном процессе
  живёт только один) и `hf-cache` с весами; у CosyVoice ещё `repo` (коммит 074ca6dc), `pretrained` и `wetext-mirror`.
  Ставится кнопкой в пульте через `uv` (`gateway/src/voice_lab/engine_installer.rs`), версии — в `requirements/`. Если рядом
  есть готовый стенд `../self-voice-tests`, его окружение копируется (на Маке это APFS-клон — место не тратится).
- `imprint.py` — разовая задача «снять отпечаток»: лучший кусок речи 5–8 с → `ref.wav`; слова от нашего распознавания;
  `voice.pt`; три пробные фразы; `meta.json`. Прогресс — JSON-строками в stdout.
- `server.py` — синтез голосами одной модели, тот же OpenAI-совместимый API, что у `tts-server`:
  `POST /v1/audio/speech {"model", "voice": "<id>", "input"}` → WAV 24 кГц (VoxCPM — 48 кГц, шлюз приводит сам);
  `GET /health` (с памятью сервера). Порты: omnivoice 8093, cosyvoice3 8094, voxcpm 8095. Запускает и гасит его шлюз;
  он работает, только пока выбран свой голос этой модели.
- `voicelab/` — общий код: WAV и выбор образца (`audio.py`), модели (`engines.py`), память (`limits.py`).

Голоса лежат в `data/voice-lab/voices/<id>/`: `meta.json`, `ref.wav`, `voice.pt`, `samples/`, `takes/`. В git не
попадают никогда. Голоса персонажей из пакетов шлюз раскладывает туда же, в `c-<пакет>-<персонаж>-<модель>/`
(`meta.json` с `origin: "package"`), и убирает вместе с пакетом; снимка под модель нет или ревизия весов другая —
снимок снимается из `ref.wav` пакета (`imprint.py --ref-text`: слова известны, распознавание не нужно).

## Память

Расчёт не должен теснить колонку, а числа в гигабайтах владелец не задаёт — защита автоматическая:

- **перед стартом** шлюз сравнивает, сколько нужно модели (замер прошлых запусков с запасом 15 %, до первого замера —
  оценка), со свободной памятью за вычетом запаса для колонки (2 ГБ или 6 % памяти, `VOICE_LAB_RESERVE_MB`). Не
  хватает — это предупреждение, а не отказ: пульт показывает цифры и запускает «всё равно» (`"anyway": true`, без него
  ответ 428). Отказа нет вовсе: если компьютеру уже не хватает памяти (давление, подкачка с диска, видеопамять) — это
  тоже предупреждение, снять «всё равно» решает владелец;
- **во время отпечатка** сторож шлюза раз в 2 секунды смотрит на систему и останавливает расчёт, если Мак 6 секунд
  подряд подкачивает память с диска (больше 10 МБ/с) или растёт давление памяти: колонка важнее. Запущенный «всё
  равно» долгое предупреждение о давлении не останавливает — владелец его видел; критическое давление и подкачка
  останавливают;
- **потолок от сбоя** — в полтора раза выше нужного (не меньше +1 ГБ): процесс сам меряет свою память раз в секунду (на
  Маке phys_footprint с видеопамятью: RSS её не видит) и уходит с понятной причиной, а чуть выше его убивает ядро —
  `taskpolicy -m … -P kill` на Маке, scope `systemd-run` с `MemoryMax` на Linux, Job Object на Windows. Так при утечке
  умирает расчёт, а не шлюз; плюс потолок аллокатора `torch.mps/cuda.set_per_process_memory_fraction`.

Пики шлюз запоминает в `data/voice-lab/engines.json`: отпечаток — по итогу задачи, сервер голоса — по `GET /health`
(`memoryMb`, `peakMb`; хранится наибольший).

Замеры на M4 Max (06.11.2026, запись стенда, три пробные фразы):

| | время | пик памяти | RTF |
|---|---|---|---|
| OmniVoice, отпечаток на процессоре | 56 с | 3,0 ГБ | 5,7 |
| OmniVoice, отпечаток на MPS | 17 с | 6,5 ГБ | 1,2 |
| OmniVoice, сервер на процессоре | старт 13,5 с | 0,8 ГБ | ~4,4 |
| OmniVoice, сервер на MPS: загрузка → после двух фраз по 5,5 с | старт 6,8 с | 4,1 → 5,4 ГБ | 0,8 |
| CosyVoice 3, загрузка на процессоре | — | > 6,5 ГБ | — |
| VoxCPM, отпечаток на процессоре (bf16; при загрузке проходит копию в float32) | — | пик 11,9, работа 7,5 ГБ | 9,4 |
| VoxCPM, сервер на MPS (float32, 48 кГц) | старт ~75 с | 11,8, пик 14,3 ГБ | 1,3 |
| OmniVoice, установка «с нуля» кнопкой (пустой кеш uv, без стенда) | 1 мин 46 с | — | — |

Установка с нуля скачивает около 1 ГБ пакетов и 3 ГБ весов (`k2-fsa/OmniVoice` @ c5fdb5cc, 13 файлов); на диске
`runtime/omnivoice` занимает около 4 ГБ, ещё около 1 ГБ — кеш uv.

Поэтому отпечаток снимается на процессоре: так он берёт вдвое меньше памяти. Говорит голос на видеокарте.

## Руками

```bash
# отпечаток (шлюз делает то же самое кнопкой)
runtime/omnivoice/env/bin/python imprint.py --engine omnivoice --runtime runtime/omnivoice \
  --takes take1.wav take2.wav --out ../data/voice-lab/voices/v-test --name "Мой голос" \
  --asr-url http://127.0.0.1:8090/v1 --device cpu --mem-limit-mb 4000 --samples '["Привет!"]'

# отпечаток из готового образца с известными словами (так шлюз снимает голоса персонажей)
runtime/omnivoice/env/bin/python imprint.py --engine omnivoice --runtime runtime/omnivoice \
  --takes ref.wav --ref-text "Слова образца." --out ../data/voice-lab/voices/c-test --name "Персонаж" --device cpu

# сервер
runtime/omnivoice/env/bin/python server.py --engine omnivoice --runtime runtime/omnivoice \
  --voices ../data/voice-lab/voices --port 8093
curl -s localhost:8093/health
```
