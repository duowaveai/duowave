# Как написать плагин шлюза

Плагин — пакет без пересборки шлюза: `manifest.json` и код. Обычно код — `backend.js` (ES-модуль в QuickJS внутри
шлюза); бывает `backend.wasm`, MCP-сервер в сети или своя программа (приложение). У каждого плагина свой контекст,
свой бюджет памяти и лимит времени, и он может только то, что попросил в манифесте и одобрил администратор. Схема
целиком — `docs/plans/plugins.md`; живые примеры — встроенные пакеты в
[`packages/`](../../packages) («Радио», погода, новости, своя музыка, сказки, игры, утреннее шоу, умный дом).

Писать удобнее всего в мастерской: раздел пульта «Мастерская», агент в ней, `duowave plugin …` в терминале или
MCP-сервер мастерской для Claude Code (ниже, «Мастерская»).

## Пакет

```
$PACKAGES_DIR/<id>/<версия>/       PACKAGES_DIR по умолчанию — $DATA_DIR/packages (пакеты всех видов)
  manifest.json
  backend.js                       один файл: import не поддерживается, собирайте esbuild в один модуль
  backend.wasm                     вместо backend.js при "runtime": "wasm"
  panel.js, panel.css              часть плагина в пульте (необязательна)
  examples.json                    пример: подставные ответы сети для плитки и «Примерки» до «да» (необязателен)
  assets/                          файлы, которые колонка играет по /media/packages/<id>/<путь>
```

Новая версия — новая папка рядом. Плагин ставится выключенным; включает администратор
(`POST /api/v1/packages/<id>/enable`): код сначала запускается, и не запустился — плагин остаётся выключенным с
причиной. `POST /api/v1/packages/<id>/reload` поднимает новейшую версию рядом с работающей: поднялась — работает
она, нет — остаётся прежняя (и после перезапуска шлюза тоже). Прежняя версия остаётся на диске:
`POST /api/v1/packages/<id>/rollback` возвращает её.

**Вид пакета** ставит шлюз, а не манифест: плагин не может объявить себя системным.

| Вид | Откуда | Выключить | Удалить | Править |
|---|---|---|---|---|
| системный (`system`) | в сборке шлюза | нет | нет | нет |
| встроенный (`bundled`) | в сборке шлюза (`packages/bundled.json`) | да | нет: обновляется вместе со шлюзом | «Сделать свою копию» |
| свой (`user`) | мастерская или папка, положенная руками | да | да | да, в мастерской |
| из каталога (`catalog`) | лента каталога | да | да | «Сделать свою копию» |

«Сделать свою копию» (`POST /api/v1/packages/<id>/fork`): копия `my-<id>` со своими настройками, оригинал
выключается, копия включается вместо него и правится в мастерской; обновление шлюза или каталога её не трогает.

## Манифест

```json
{
  "schema": 1,
  "kind": "plugin",
  "id": "radio",
  "version": "1.1.0",
  "title": "Радио",
  "description": "Что он делает — для пульта",
  "api": "^2",
  "runs": ["pc", "station", "stationServer"],
  "budget": { "memoryMb": 4, "storageMb": 1 },
  "permissions": ["net:*.api.radio-browser.info"],
  "settings": [{ "key": "country", "type": "string", "title": "Страна", "default": "RU" }],
  "contributes": {
    "intents": [{ "phrases": ["включи радио {station}"], "handler": "playStation", "capability": "radio" }],
    "tools": [{ "name": "radio_search", "description": "Ищет станции", "input": { "type": "object", "properties": {} },
                "handler": "radioSearch", "annotations": { "readOnlyHint": true } }],
    "media": [{ "id": "stations", "kind": "radio", "handler": "stations" }],
    "events": [{ "name": "player.silent", "handler": "onPlayer" }],
    "panel": { "calls": ["radioCard"], "cards": [{ "id": "stations", "title": "Радио", "function": "radioCard" }] }
  }
}
```

| Поле | Что значит |
|---|---|
| `schema` | версия формата манифеста, сейчас `1` |
| `kind` | вид пакета: `plugin` (по умолчанию), `app`, `character`, `theme` — формат один для всех видов. Код запускается у `plugin` и `app`; персонаж и тема — данные без кода |
| `id` | строчные латинские, цифры, `-`; совпадает с папкой |
| `version` | semver; совпадает с папкой |
| `api` | какой Host API нужен: шлюз даёт **2.0**, пишите `"^2"`. Приложение для Host API 1 не ставится и не включается — его переделывают в мастерской. У персонажа и темы (данных без кода) версия не важна |
| `runtime` | движок: `js` (по умолчанию), `wasm`, `mcp`; у приложения — `process` |
| `runs` | где работает: `pc`, `station` (шлюз на колонке), `stationServer` (колонка + домашний сервер) |
| `prefer` | `"home"`: в режиме «колонка + сервер» вызовы идут на компьютер, пока он на связи (ниже) |
| `budget.memoryMb` | лимит памяти, 1–64, по умолчанию 4: выше — вызов падает, шлюз жив. На колонке — ещё и доля общего бюджета |
| `budget.storageMb` | сколько места под `kv`, 1–64, по умолчанию 1 |
| `budget.filesMb` | своя папка приложения (`host.files`, картинки), по умолчанию 64 МБ |
| `permissions` | права, ниже |
| `settings` | поля настроек: `string` (можно `options`), `number`, `boolean`; пульт рисует форму сам. `"secret": true` у `string` — тайное значение (ниже) |
| `contributes` | что плагин даёт шлюзу, ниже |
| `dataVersion` | необязательно: целое — вид данных, которые плагин хранит (`kv`, задачи, картинки). Поднимайте его, когда меняете, как устроены сохранённые данные: возврат к версии с другим `dataVersion` предупредит, что старый код может не понять сегодняшние данные (ниже, «История») |

Шлюз проверяет манифест целиком и называет все ошибки сразу (`GET /api/v1/packages` → `versions[].problems`).

Настройка с `"secret": true` (только у `string`: ключ API, тайная ссылка календаря) наружу не отдаётся: в
`GET /api/v1/packages…` и в `useSettings` вместо заданного значения — «••••••», пустое так и остаётся пустым. Форма
пульта показывает пустое поле «задано · впишите новое, чтобы заменить». Сохранили, не трогая его, — пришла маска, и
значение остаётся прежним; новое значение заменяет его, `null` в `PUT /api/v1/packages/<id>/settings` убирает. Бэкенд
плагина (`host.settings.get`) и программа приложения (`GET /api/v1/apps/host/settings`) получают значение как есть.

Хранит его сейф шлюза — тот же, что ключи моделей (AES-256-GCM), под именем `plugin:<пакет>:<ключ>`, а не настройки
пакетов: в базе и её копиях открытого ключа нет. Копия плагина («Сделать свою копию») берёт ключи с собой, удаление —
убирает. При переезде они едут, как ключи моделей, — запечатанными ключом пары. Журнал плагина (и агенту мастерской, и
в журнале шлюза) прячет известные ключи как «•••», ключи плагинов — от 4 знаков. Значения, записанные шлюзом постарше
среди настроек, первый же запуск переносит в сейф.

Настройки вписывают и до первого запуска: «Примерка» отдаёт их установке (`POST /api/v1/workshop/drafts/<id>/install
{approve, settings}`) — шлюз сверяет каждое с манифестом и пишет до запуска, так что плагин с ключом с первого вызова
работает с ключом. Пока «да» не дано, ключ живёт только в памяти страницы.

### Права

С Host API 2 прав два вида — и только они:

| Право | Что даёт |
|---|---|
| `net:<хост>`, `net:*.<домен>` | `host.http.fetch` к этому хосту или поддоменам (и `host.files.download`); другие хосты, адреса самого компьютера, не http(s) — отказ |
| `see:<адрес>`, `listen:…`, `call:…`, `edit:…` | связь на шине: видеть участника, слышать его новости, звать его умения (у файлов — читать), править (у файлов — класть, менять, удалять). `call:system/voice`, `call:app/notes`, `listen:device/midi`, `edit:files/home/Документы/*` — ниже, «Шина» |

Что приложение даёт — фразы, инструменты «Мозга», источники для плеера, события, ритмы, карточки — не права: это
`contributes`, и администратор видит их при установке. Своё хранилище (`host.kv`) и своя папка (`host.files`) — без
прав. Слово Host API 1 (`voice.say`, `smart_home`, `kv`…) в `permissions` — ошибка манифеста с подсказкой, чем оно
стало.

Первая установка и каждый новый хост в интернете — после «ок» администратора в пульте. Связи спрашиваются у человека
«да» при первом обращении, как в телефоне: «Разрешить» и «Не разрешать» запоминаются; у встроенных приложений их
связи даны с установкой, владелец может убрать их в «Связях».

### Что даёт плагин

- **`intents`** — фразы, как у быстрых правил шлюза: вся команда целиком, без регистра и знаков, со «слотами»
  `{имя}`. Фраза начинается со слова, два слота подряд нельзя, имя `request` занято. Фразы плагина забирают слова,
  которых не знают встроенные правила, и слова встроенного правила **той же** возможности (`capability`) —
  тогда, если плагин вернул `null` или упал, фразу обслуживает встроенный навык. Управление колонкой («стоп»,
  «громче», «дальше», таймеры, будильники, звонки) плагину не отдаётся никогда. `capability` — из каталога
  возможностей (`radio`, `music`, `weather`…); для неё действуют её маршрут и право человека (`use:radio`). Без
  `capability` — общая `plugins` (`use:plugins`, у гостей её нет).
- **`tools`** — инструменты «Мозга» в форме MCP: `name` (строчные, `_`), `description` (по ней модель выбирает),
  `input` — JSON Schema объекта. `annotations.readOnlyHint: true` — инструмент ничего не меняет и остаётся
  доступен после текста из интернета. Модель видит их рядом со встроенными и MCP — в разговоре колонки и в
  проверочном чате. Проверить без модели: `POST /api/v1/packages/<id>/tools/<name>/try` `{"arguments": {...}}`.
- **`media`** — источник для встроенного радио (`kind: radio`), музыки (`music`) или сказок (`tales`): функция
  получает `{query, limit}` (без `query` — что играть подряд) и отдаёт элементы. Звук идёт плеером шлюза, поэтому
  «пауза», «дальше», «громче» работают встроенными навыками. Источник плагина важнее встроенного запасного
  (список `content/radio.json`, папки `content/`): пока он есть, встроенный не спрашивают.
- **`events`** — `station.connected`, `station.disconnected`, `mode.changed`, `homeServer.up`, `homeServer.down`:
  функция получает `{name, payload}`, в фоне. События плеера — о **своём** элементе, который играет плеер шлюза:
  `player.started`, `player.stopped`, `player.failed`, `player.silent` (колонка молчит N с), в `payload` —
  `{device, item: {id, title, url}, viaGateway, seconds, retrying}`. На `player.failed` и `player.silent` без
  `retrying` можно ответить `{play: [...]}` — что играть вместо (так «Радио» переходит к похожей станции и запоминает
  нерабочую).
- **`schedules`** — ритмы: «по будням в 7:30», «каждые 2 часа с 9 до 21» — в срок шлюз зовёт функцию или сам говорит
  готовую фразу (ниже, «Расписание»).
- **`bus`** — его часть на шине (ниже, «Шина»): `emits` — новости, которые он рассказывает; `on` — чьи новости он
  слушает (`{from, event, handler}`, нужно право `listen:` на того, кого слушает); `ask` — функция, что отвечает на
  вопрос словами; `private` — умения, открытые только связью, которую владелец поставил сам; `danger` — свои умения,
  что он сам помечает опасными (`{"wipe": "delete"}`; метку можно только добавить).
- **`panel`** — часть плагина в пульте: карточки (`cards`) и своё окошко (`panel.js`), ниже, «Пульт»;
  **`themes`** — темы пульта; **`characters`** — персонажи
  (`docs/plans/characters.md`). У пакетов `character` и `theme` нет кода: `intents`, `tools`, `media`, `events` —
  только у плагина и приложения.

## Функции и ответы

`handler` — имя функции, которую экспортирует `backend.js`. Функция получает один объект и может быть `async`.

| Кто зовёт | Получает | Отдаёт |
|---|---|---|
| фраза (`intents`) | слоты и `request: {text, device, timezone, capability}` | строку (речь), ответ-объект (ниже) или `null` — «не моё» |
| продолжение разговора (`continue`) | `{text, request}` — следующие слова человека; с таймером хода ещё `timer: {seconds, spent}` | то же, что фраза |
| таймер хода (`continue.timeout`) | `{timeout: {seconds, missed}, request}` — человек промолчал | то же, что фраза; колонка говорит это сама |
| инструмент (`tools`) | аргументы модели | любой JSON или строку — модель читает текст, до 16 КБ; `{say, play}` — действие |
| источник (`media`) | `{query, limit}` | список элементов или `{items: [...]}`, до 100 |
| событие (`events`) | `{name, payload}` | ничего; на `player.failed`/`player.silent` — `{play}` |
| пульт (`panel.calls`) | что прислал `panel.js` | любой JSON |

Ответ-объект на фразу — поля можно сочетать:

| Поле | Что делает | Право |
|---|---|---|
| `say` | речь голосом Алисы, до 1000 знаков | — |
| `play`, `index` | список элементов для плеера шлюза и с какого начать | — |
| `listen` | колонка слушает дальше без «Алиса» | — |
| `display: {temperature}` | температура на экране колонки | — |
| `model: {system, prompt, key, fresh}` | ответ говорит модель шлюза: `system` — роль и правила, `prompt` — вопрос (по умолчанию слова человека), `key` — своя история разговора на колонке, `fresh` — начать её заново. Ответ идёт колонке по фразам, по мере готовности | `llm.chat` |
| `continue` | `true` или `{handler}`: следующие слова человека (3 минуты, без «Алиса») идут снова в плагин — в ту же функцию или в названную; игры, уточняющие вопросы. `{handler, timeout}` — ещё и таймер хода (ниже) | — |

### Таймер хода — «Время вышло!»

Для игр на время: человек молчит дольше `seconds` — колонка сама говорит «время вышло».

```js
const next = { handler: "answer", timeout: { seconds: 10, handler: "timeUp" } };

export function start() {
  return { say: "Столица Австралии?", continue: next };
}

// Человек начал говорить до срока: обычный ход; timer.spent — сколько секунд он думал
export function answer({ text, timer }) {
  return { say: /канберр/.test(text) ? "Верно! Столица Канады?" : "Нет, это Канберра. Столица Канады?", continue: next };
}

// Тишина: timeout.missed — какая это тишина подряд
export function timeUp({ timeout }) {
  return { say: "Время вышло! Это Канберра. Столица Канады?", continue: next };
}
```

- **`timeout`** — только внутри `continue`: `{seconds, handler}` или готовое `{seconds, say}` — готовое колонка говорит,
  и разговор кончается. `seconds` — от 3 до 120. Поставлено не так — таймер не встаёт, причина в журнале плагина.
- **Отсчёт — с конца речи колонки**: шлюз знает, сколько звука ей отправил. С `play` — тоже с конца речи, отрывок
  играет внутри этих секунд.
- **Успел тот, кто начал говорить до срока**: слова идут в функцию разговора с `timer: {seconds, spent}`.
- **Функция таймера** отвечает, как на фразу (`say`, `play`, `model`, `continue` с новым таймером); колонка говорит
  это без запроса и слушает после, если разговор идёт дальше.
- **Две «время вышло» подряд** шлюз терпит; на третьей тишине он сам говорит «Похоже, никого нет — заканчиваю» и
  кончает разговор, плагин уже не зовёт. Речь по таймеру не продлевает 3 минуты разговора — их продлевают только
  слова человека.
- **Снимается сам**: разговор кончился, звенит будильник или таймер, колонка пропала со связи, плагин выключили или
  обновили, шлюз перезапустили; опоздал больше чем на свою длину (Mac спал) — снимается молча.
- **Без «Алиса» колонка слушает около 5 с**: таймер длиннее — под конец человек отвечает с «Алиса», слова всё равно
  идут в игру. Мастерская об этом предупредит.
- Номер вопроса и счёт — в `kv`: память кода между ходами не живёт. Заготовка — «Викторина на время» в мастерской
  (`duowave plugin new <id> --quiz`).

**Инструменты делают, а не только находят.** Ответ инструмента вида `{say, play}` шлюз выполняет сразу, если
«Мозг» позвал его в разговоре колонки: станция включается, модель читает «Playing …» и говорит одной фразой. В
ответ поиска кладите подсказку следующего шага («нашла 3 станции; включить — `radio_play`»).

### Элемент для плеера

`{id, title, url | path | content | stream, format?, type?, subtitle?, imageUrl?, durationMs?}`:

- `url` — поток в интернете, колонка берёт его сама;
- `path` — файл из `assets/` пакета (`/media/packages/<id>/<путь>`);
- `content` — файл семьи из `CONTENT_DIR`, путь от папки (`music/Альбом/1.mp3`), только с правом `content:<папка>`;
- `stream` — свой звук приложения (ниже, «Приложения»).

`format` — `HLS` или `MP3` (любой кодек файла — `MP3`, как у Яндекса); по умолчанию по ссылке. `type` — `FmRadio`,
`Track`, `FairyTale`, `AudioBook`; по умолчанию по виду источника.

**Потоки из интернета — только по https.** Поток по http колонка не играет: молчит и не сообщает об ошибке
(проверено 07.11.2026: «Хит FM» по https играет, «Радио Джаз» по http — нет). Проверенно играют MP3 и HLS; AAC колонка
не играет («Радио Рекорд», 07.11.2026). Часть серверов молча не играет и по https («Радио Джаз» с
`main.hostingradio.ru`). Поэтому шлюз следит за плеером: колонка молчит 5 с — он сам открывает поток и отдаёт его
колонке через свой `/media` (AAC перекодирует в MP3 на компьютере; на колонке — только с
`MEDIA_TRANSCODE_ON_STATION=1`), а не помогло — плагину приходит `player.silent`. Что колонка ответила, видно в
журнале запроса и журнале плагина.

## Host API 2

Глобальный `host` — всего шесть частей. Всё, что вне самого приложения, — письмо шины (ниже, «Шина»): шина решает его
по связям, отказ — исключение с причиной.

```js
await host.http.fetch(url, { method, headers, body, timeoutMs })  // → {status, ok, url, headers, text(), json()}
host.kv.get(key) · host.kv.set(key, value) · host.kv.delete(key) · host.kv.keys(prefix)   // своё хранилище
host.settings.get(key?)                                           // значения настроек из манифеста
host.log(...) · console.log / warn / error                        // в журнал шлюза и журнал приложения
host.plugin                                                       // {id, version}
host.api                                                          // 2

await host.bus.call(to, handle, input)    // письмо: умение участника — службы, приложения, папки, устройства
await host.bus.ask(to, text)              // вопрос словами
await host.bus.tell(event, payload)       // своя новость (contributes.bus.emits)
await host.bus.list()                     // кого видит приложение и что они умеют
host.files.read / write / list / move / mkdir / stat / remove / download   // своя папка и папки дома (ниже)
```

Службы шлюза — участники шины, каждая по своей связи:

```js
await host.bus.call("system/voice", "say", { text, device })        // call:system/voice → сказано ли (без запроса)
await host.bus.call("system/notify", "send", { text })              // call:system/notify → сообщение владельцу
await host.bus.call("system/schedule", "set", task)                 // call:system/schedule → {id, next}
await host.bus.call("system/schedule", "list" | "cancel" | "parse", …)
await host.bus.call("system/smart-home", "devices")                 // call:system/smart-home → [{id, name, kind, state}]
await host.bus.call("system/smart-home", "act", { device, action, value })  // on, off, set_brightness, set_temperature, scene
await host.bus.call("system/content", "music" | "tales", { query, limit })  // call:system/content → готовые элементы для play
await host.bus.call("system/home", "weather-place" | "news-feeds")  // call:system/home → что выбрано в пульте
await host.bus.call("app/weather", "weather_now", { place })        // call:app/weather → инструмент другого приложения
```

Ответ `model` у фразы (модель шлюза говорит словами приложения) — по связи `call:system/brain`.

Нет `setTimeout`, файловой системы и процессов: код работает, только когда его позвали. Ждать ответа человека по
времени — таймер хода (выше).

## Шина: другие приложения, папки, устройства

Всё, что живёт в системе, — участник с адресом (план): приложение `app/<id>`, службы шлюза
`system/notify`, `system/schedule`, `system/smart-home`, `system/content`, папки `files/…`, устройства `device/midi`.
Приложение пишет другому письмо — шина решает одним правилом, пройдёт ли оно:

- **Чего приложение не просило, того для него нет**: ответ «нет такого», без намёка, что оно есть.
- **Что оно попросило в манифесте** (`call:app/notes`) — при первом обращении человек видит вопрос «да», как в
  телефоне; «Разрешить» и «Не разрешать» запоминаются (поменять — в окне приложения, «Связи»). Пока вопрос ждёт —
  письмо получает ошибку «ждёт вашего «да»»: скажите человеку, что разрешить можно в пульте.
- **Встроенные приложения** — наши, в сборке шлюза: их связи даны с установкой («при установке» в «Связях»),
  владелец может их убрать.
- **Цепочка не больше того, кто начал**: фраза гостя через приложение не включит свет, если гостю нельзя; письма
  одной цепочки — до 32, шагов от приложения к приложению — до 4, круг (A → B → A) — отказ.
- **Опасное** (`money`, `delete`, `outside`, `locks`, `camera`, `access`; инструмент с `destructiveHint` или
  `openWorldHint`) без человека в начале цепочки спрашивает «да» каждый раз и разрешается на одно действие.
- **Режимы**: «По правилам» (по умолчанию), «Свободно» (всё открытое — до «звать», личное и опасное — всё равно через
  людей), «Отдельно» (ни с кем). У дома — свой, у приложения — свой поверх.
- Два приложения без человека зовут друг друга не больше 30 раз в сутки: дальше — до завтра.

```js
await host.bus.call(to, handle, input, { files })  // письмо: умение участника (инструмент, функция пульта, папка)
await host.bus.ask(to, text)                       // вопрос словами: {text} — его функцией ask или, без неё, моделью
                                                   //   «Мозга» с его инструментами (облачной — если владелец разрешил)
await host.bus.tell(event, payload)                // новость из contributes.bus.emits — тем, кому можно её слышать
await host.bus.list()                              // кого видит приложение и что они умеют: [{address, title, handles}]

// Папки: адрес files/… или путь в своей папке files/app/<id>/ — своя папка без прав
await host.files.write("tmp/a.txt", "текст")       // или { base64 }; tmp/ чистится сама через сутки
await host.files.read("tmp/a.txt", { as: "text" }) // → {text} или {base64}, {size, type}
await host.files.list("tmp")                       // → {items: [{name, size, folder, modified}]}
await host.files.move(from, to) · host.files.mkdir(at) · host.files.stat(at) · host.files.remove(at)
```

Общие папки дома — `files/home/Картинки`, `Фото`, `Видео`, `Документы`, `Загрузки` (по праву `call:`/`edit:`);
`Музыка` и `Сказки` — только читать. Чужое удаляется в корзину на 7 дней. Своя папка — до `budget.filesMb` (64 МБ
по умолчанию); на колонке файл до 1 МБ, все файлы — до 5 МБ. Личные папки людей (`files/person/<id>`) — только по
связи, которую владелец поставил сам; приложение о них не спрашивает.

Журнал шины пишет, кто кому писал, когда и чем кончилось, — без содержимого писем. Видно в пульте: окно приложения
→ «Связи» → «Журнал связей», «Настройки» → «Связи приложений» → «журнал».

## Расписание — приложение само в срок

Связь `call:system/schedule` (готовая речь — ещё `call:system/voice`, сообщение — `call:system/notify`). Сроки хранит
шлюз, приложение загружается только на свой срок; такт — 15 с.

```json
"permissions": ["call:system/schedule", "call:system/voice"],
"settings": [{ "key": "time", "type": "string", "title": "Во сколько", "default": "07:30" }],
"contributes": { "schedules": [
  { "id": "brief", "title": "Сводка утром", "at": "{time}", "days": "weekdays", "handler": "brief" },
  { "id": "water", "title": "Попить воды", "every": "2h", "from": "09:00", "to": "21:00", "say": "Пора попить воды" }
] }
```

- **Ритм манифеста** — `at` (`ЧЧ:ММ` или `{ключ}` строковой настройки — время выбирает человек) с `days`
  (`daily`, `weekdays`, `weekends`, `["mon", "wed"]`), или `every` от `5m` до `1d` в окне дня `from`–`to` (по умолчанию
  08:00–22:00). До 10 ритмов. Время — там, где колонка: в день перевода часов несуществующее время сдвигается вперёд,
  из двойного берётся первое.
- **Задача из кода** — `host.bus.call("system/schedule", "set", {after: 3600 | once: "2026-11-20T18:00" | at, days |
  every, from, to, handler | say, id?, title?, data?, device?})`: `after` — секунды (не меньше минуты: короче — таймер хода, он в разговоре),
  `once` — дата и время дома, не дальше года. Тот же `id` заменяет задачу; ритм манифеста код не трогает — его ставит
  на паузу человек в пульте. `device` — колонка, где сказать (`request.device`), без него — любая на связи.
- **Ответ задачи**: функция (`handler`) получает `{schedule: {id, title, due, late}, data}` и отдаёт строку или
  `{say}` — колонка говорит (связь `call:system/voice`), `{notify}` — сообщение владельцу (`call:system/notify`; можно вместе),
  `null` — сделала дело молча. Или **готовый ответ** вместо функции — `say: "…"` и (или) `notify: "…"`: шлюз говорит
  и присылает его сам и плагин не загружает. Что можно сказать готовым — ставьте готовым.
- **Сообщение владельцу** (`notify`) уходит теми же путями, что оповещения о колонке: чат «Оповещения» в Telegram,
  вебхук `ALERT_WEBHOOK_URL`, уведомление Mac; в начале — название плагина. Не больше 20 в час на плагин. Пути нет —
  письмо `system/notify` отвечает причиной («выберите чат «Оповещения»…»). На колонке Telegram-бота нет: там — вебхук.
- **Разбор времени**: `host.bus.call("system/schedule", "parse", { text: "каждый день в девять пить таблетки" })` → `{spec: {at: "09:00", days:
  "daily"}, rest: "пить таблетки"}` — понимает «каждый день / по будням / по выходным в …», «каждые 2 часа», «через 10
  минут», «завтра в 18:00».

**Предохранители** — у шлюза, плагин их не обходит: речь по расписанию — не больше 12 раз в час на плагин; задач из
кода — до 50, `set` — до 60 в час; после перерыва (Mac спал, шлюз был выключен) — не больше 3 опоздавших речей подряд,
повторы пропущенное не догоняют, разовая задача, опоздавшая больше чем на 6 часов, снимается; колонка звенит или с ней
говорят — речь ждёт; колонки нет на связи — речь ждёт (разовая — до 6 часов, повтор — до следующего раза); 5 ошибок
подряд — пауза с причиной. `PLUGINS_SCHEDULES=0` останавливает все расписания, задачи сохраняются. Сроки ведёт шлюз,
у которого сессия колонки: компьютер, который только помогает колонке, их не ведёт.

| Нужно | Чем |
|---|---|
| «10 секунд на ответ» в игре | таймер хода (`continue.timeout`) |
| в срок сказать одно и то же | ритм или задача с готовым `say` |
| в срок что-то узнать или решить | ритм или задача с `handler` |
| следить за чем-то (новые встречи, курс) | ритм `every` с функцией, находки — разовыми задачами |

## MIDI-клавиатура

Клавиатуру (USB, на Mac — и Bluetooth) слышит шлюз на компьютере: в окне приложения DuoWave Web MIDI нет, а так она
работает и там, и в любом браузере, и с планшета дома. Связь `listen:device/midi`, `"runs": ["pc"]` (без `pc` —
проблема манифеста); слышит её окошко приложения (`panel.js`). Заготовка — `midi` («Учитель на MIDI-клавиатуре»), `duowave plugin new <id> --midi`.

```js
import { PianoKeys, useMidi, useSynth } from "@duowave/panel-sdk";

const midi = useMidi();            // state: ready | nodevice | browser | off | example; why — словами
const synth = useSynth();          // needsTap — пока нет нажатия на странице, звука нет: кнопка «Начать»
useEffect(() => midi.on((e) => {
  if (e.type === "on") synth.down(e.note, e.velocity);
  if (e.type === "off") synth.up(e.note);
  if (e.type === "pedal") synth.pedal(e.down);
}), [midi, synth]);
return h(PianoKeys, { from: 48, to: 72, next: [60], onDown: (n) => midi.press(n), onUp: (n) => midi.release(n) });
```

- **Только в пульте.** Ноты приходят `panel.js` своего приложения по своему каналу (`/api/v1/midi/ws`), только дома
  (`MIDI_REMOTE=1` — и вне дома); бэкенду не приходят: вызов на каждую клавишу будил бы его зря. Что запомнить —
  `panel.js` отдаёт своей функции, одним вызовом.
- **Клавиатура открыта, пока её слушают**: шлюз открывает её для первой страницы и отпускает через 10 с после
  последней; страница спрятана дольше минуты — канал закрыт. Слушайте в окне, не в виджете стола.
- **В клавиатуру**: `midi.send({ type: "on", note, velocity })`, мелодия — `midi.play([[нота, сила, начало мс, длина
  мс]])` (до 2000 нот и 10 минут, играет шлюз по своим часам). Только сообщения каналов; SysEx — нет. Ушла страница —
  шлюз отпускает её ноты, «все ноты выкл.» и педаль.
- **Звук** — `useSynth()`: простой «рояль» на Web Audio; `playAll([[нота, начало, длина]], { tempo, onNote })` — в
  долях, по часам звука. `delayMs` больше 80 — скорее наушники по Bluetooth: предупредите.
- **Файл `.mid`** — `readMidiFile(file)`: шлюз читает его (до 256 КБ) и отвечает дорожками с верхним голосом; файл
  нигде не хранится. `melodyOf(дорожка)`, `noteName(60)` → «до первой октавы».
- **Пример**: в «Примерке» и мастерской `state: "example"` — клавиатура на экране; своя подключится после «да».
- **Запасной путь**: шлюз без клавиатуры (программа `duowave` для Linux), а пульт — Chromium на `localhost` или по
  https: `state: "browser"`, кнопка зовёт `midi.useBrowser()`. «Проверить» предупреждает о Web MIDI без связи `listen:device/midi`.
- Где клавиатура и кто её слушает — `GET /api/v1/midi`; строка реестра `plugins.midi`; `MIDI=0` — без клавиатур.

## Картинки

Хост картинки в `net:`. `host.files.download(url, name)` — шлюз сам скачивает картинку в корень своей папки приложения,
мимо памяти плагина, и сверяет тип по первым байтам: годятся PNG, JPEG, WebP, GIF. Имя — латиница, цифры, «-», «_»;
расширение шлюз ставит по типу. Тот же `name` заменяет картинку. В пульте плагин показывает её хуком
`useFile(name)` из SDK или деталью `picture` карточки — шлюз отдаёт её только с ключом пульта, открытой ссылки нет.

- **На компьютере** картинка — до 10 МБ, вся своя папка — в `budget.filesMb`.
- **На колонке** места мало: картинка — до 1 МБ, все картинки всех плагинов вместе — до 5 МБ. Не влезло — `download`
  отвечает причиной. Плагин с `"prefer": "home"` в «колонка + сервер» держит картинки на компьютере. Мастерская на колонке
  об этом предупреждает.
- **Переезд** везёт картинки вместе с данными плагина: на компьютер — все, на колонку — сколько влезет в 5 МБ, новые
  первыми. Поэтому приложение проверяет `host.files.list()` и качает недостающее.
- Удалили плагин — его картинки удаляются с ним. В карточке плагина — «Картинки: 3 · 2,1 МБ из 5».

## Лимиты

| Что | Сколько |
|---|---|
| вызов фразы, инструмента, источника | 2 с, ожидание сети и очередь к плагину включительно |
| фоновый вызов (событие) | 30 с |
| загрузка кода (верхний уровень модуля) | 2 с |
| память контекста | `budget.memoryMb` |
| `backend.js` / `backend.wasm` / `manifest.json` | 1 МБ / 4 МБ / 64 КБ |
| ответ функции | 256 КБ JSON |
| `fetch`: ответ / тело запроса / свой тайм-аут | 1 МБ / 256 КБ / 5 с, не больше 10 с; до 5 перенаправлений, каждое по правам |
| `kv`: ключ / значение / всё хранилище | 200 Б / 64 КБ / `budget.storageMb` |
| журнал | 50 строк за 10 с, остальное отбрасывается |
| таймер хода | 3–120 с, один на колонку; две «время вышло» подряд, третья тишина кончает разговор |

Вызов, превысивший время или память, падает, а контекст плагина выгружается: следующий вызов начнёт с чистого.
Плагин без вызовов выгружается через `PLUGINS_IDLE_UNLOAD_S` (10 минут на компьютере, 2 на колонке) и
загружается снова при следующем. `PLUGINS_DISABLED=1` запускает шлюз без плагинов вообще.

## Память на колонке

На колонке мало памяти и нет свопа, поэтому там у плагинов общий бюджет: доступная память минус запас для системы
и Алисы (`PLUGINS_RESERVE_MB`, 40 МБ). Каждый включённый плагин занимает свой `budget.memoryMb` — объявленный, а не
фактический. Не помещается — включение отказывает с числами («не хватит памяти колонки: нужно 12 МБ, свободно 7»),
каталог показывает пакет серым. Место на диске считается так же, с запасом `PLUGINS_STORAGE_RESERVE_MB` под
обновление шлюза. Бюджет и что сколько занимает — «Настройки» → «Колонка» → «Ресурсы колонки» и
`GET /api/v1/packages/resources`.

Под давлением простаивающие плагины выгружаются, фоновые вызовы ждут; при «critical» выключается последнее
включённое приложение, а нет приложений — последний включённый плагин (`PLUGINS_PRESSURE_ACTION=warn` — только
предупреждение). Встроенное и голосовой тракт не трогаются. На компьютере бюджет только показывается.

## Где работает: колонка, компьютер, «колонка + сервер»

`runs` перечисляет размещения, где плагин может работать. В режиме «колонка + сервер» плагин с `"prefer": "home"`
исполняет компьютер: шлюз колонки зовёт его по ключу пары (`/home/v1/plugins/<id>/call`), а сам не загружает и
бюджет колонки не тратит. Что он при этом играет — свой звук приложения (`stream`) и файлы семьи (`content`), —
колонка берёт с `/media` компьютера по домашней сети. Компьютер не на связи — плагин работает на колонке, если
помещается, иначе отвечает «недоступно, пока компьютер не на связи». В карточке плагина видно, где он работает
сейчас.

## Пульт

Виджет стола — по умолчанию **карточка** ([cards.md](cards.md)): `contributes.panel.cards` и функция
`backend.js`, что отдаёт её данные из деталей пульта. Рисует пульт — кода приложения в нём нет. **Окошко** — свой
`panel.js` — для того, чего карточка не умеет: своё рисование, игра, клавиши на экране, MIDI, звук, движение.

`panel.js` — ES-модуль, который пульт загружает с шлюза (`/panel-plugins/<id>/<версия>/panel.js`), пока приложение
включено. `preact`, `preact/hooks`, `preact/jsx-runtime` и `@duowave/panel-sdk` ведут к копиям окошка (import map):
свою копию Preact приложение не везёт. Типы и пример — [`panel-sdk.d.ts`](panel-sdk.d.ts).

Код пульта любого приложения — встроенного, своего, из каталога, черновика — работает только в **своём окошке** —
изолированном фрейме `/panel/frame.html` (`sandbox allow-scripts`, без своего происхождения, `connect-src 'none'`):
у него нет ни входа человека, ни хранилища пульта, ни сети. Пульт узнаёт, что приложение приносит (разделы и вклады в
`desk.widgets`, `home.cards`, `house.tabs`), и рисует их окошками; тема, размер, настройки и номер перемены приходят
от пульта, а `useApi`, `useFile`, `ask`, переход в раздел и `useMidi` идут мостом. `useLive()` в окошке не видит
запросов людей. Сеть, чужие приложения и папки — только через свой `backend.js` и шину.

- `definePlugin({ id, sections, slots, themes })`: свои разделы и вклады в слоты `desk.widgets`, `home.cards`,
  `house.tabs` (другие слоты окошку не даются); упавший вклад скрывается, соседи живут.
- **Виджет стола** (`desk.widgets`, план стола): `{ id, title, icon, size: "small" | "large",
  source, initial, Component }`. Рамку — название, значок, источник, меню «…», перетаскивание — даёт стол; виджет
  рисует только содержимое (классы `w-big`, `w-rows` > `w-row`, `w-cap`, `w-day`, `w-btn`). `initial: true` — стоит
  на столе сразу; без него — его ставят из «+». Живые данные колонки — только чтение: `useLive()` (запросы,
  присутствие), `useStation()` (колонка, режим, роль пульта); значки — `icons`. Пример окошка — заготовка `midi`
  («Учитель на MIDI-клавиатуре»); виджеты встроенных (`weather`, `radio`, `currency`, `shopping`, `calendar`) —
  карточки. «Проверить» в мастерской разбирает и `panel.js`: ошибка синтаксиса видна там, а не в пульте, а окошко,
  что только показывает строки и кнопки, — повод сделать карточку.
- **Свежие данные**: плагин пишет в своё `kv` (`set`, `delete`) — голосом, по событию, из другого пульта, — шлюз
  говорит пульту (`packages.data`; не чаще раза в секунду на пакет, последняя запись не теряется; `set` того же
  значения — не перемена), и `usePanelState().version` растёт. Виджет, у которого `version` в зависимостях эффекта,
  перечитывает данные сам: «Алиса, добавь молоко в список покупок» — и строка уже в виджете (`packages/shopping`).
  Поэтому функция, которой виджет читает данные, в `kv` не пишет: иначе каждое чтение — перемена, и виджеты стола
  перечитываются раз в секунду, пока открыт пульт. Кэш — только по сроку: пишется, когда устарел, как в `weather` и
  `currency`; что меняет человек — пишет функция его действия (`addCard` в `shopping`). На тёмном столе помощника
  виджет плагина колонки обновляется так же: пульт слушает и живой канал колонки.
- `useApi(id).call(функция, данные)` зовёт функцию `backend.js` из `contributes.panel.calls`
  (`POST /api/v1/packages/<id>/call/<функция>`, право человека `use:plugins`); `useSettings` (тайные — маской),
  `usePanelState`;
  компоненты «Стекла»: `Card`, `Note`, `Pill`, `Action`, `Switch`, `Sheet`; вопрос перед необратимым — `await ask({ title, ok, danger })`
  (`window.confirm` в окне приложения не показывается).
- `panel.css` — только через токены темы (`var(--accent)`, `var(--text)` …).
- `?safe=1` в адресе пульта — без плагинов.

Тема без кода — пакет `kind: theme` или `contributes.themes` плагина: палитры обоих режимов (перекраска «Минимала»),
вид, который тема советует (`desk`, `sidebar`), плотность, шрифт, скругления — контракт
[`THEMES.md`](../design/glass/THEMES.md). Тема появляется в «Настройки» → «Оформление» → «Вид пульта».

## Мастерская

Черновики — `$DATA_DIR/packages-dev/<id>/`. Проверка («Проверить»): манифест, загрузка кода, функции против
манифеста и предупреждения о том, что колонка не сыграет (http, AAC), чего у приложения нет (`setTimeout`, `import`,
вызовы Host API 1) и о письмах тому, с кем манифест не просит связи. Песочница с подставным `host`: прогнать фразу как её услышит маршрутизатор,
вызвать функцию со своим входом. «Поставить» кладёт черновик новой версией рядом с прежней; первую установку и новые
права подтверждает администратор.

**Пример вместо своих данных.** До «да» черновик в сеть не ходит: плитка на столе и «Примерка» запускают его в
песочнице на примере — `examples.json` в корне черновика:

```json
{ "fetch": [ { "url": "https://api.todoist.com/rest/v2/tasks", "status": 200,
               "json": [ { "content": "Купить хлеб", "due": { "string": "сегодня" } } ] } ] }
```

`fetch` берёт ответ того примера, чей `url` — начало адреса запроса (из нескольких — самый длинный; ещё бывают
`method`, `headers`, `text` вместо `json`); нет такого — ошибка «нет примера для …», в сеть — никогда. Права
проверяются как обычно. `POST …/run` и `…/phrase` принимают `example: true` и обычные настройки `settings` («Показывать:
3» сразу видно в примере); личные (`secret`) шлюз отклоняет — их вписывают при установке. «Проверить» предупреждает,
если черновик ходит в сеть, а примера нет. Из терминала — `duowave plugin test <папка> --run panelData --example`.

- **Пульт** — «Плагины» → «Мастерская»: файлы, песочница (фразы манифеста кнопками и все разом, функция с входом
  по схеме инструмента), журнал плагина, история (шаги, версии, возврат, объединение), чат с агентом (модель агента выбирается здесь же,
  «Мозг» не меняется). «Поставить…» сначала показывает, что изменится: версию, права и хосты, что даёт. «Проба на
  колонке…» ставит черновик на 5–30 минут, потом прежняя версия возвращается сама (`POST/DELETE
  /api/v1/workshop/drafts/<id>/trial`). Тему видно сразу («Примерить тему»); свою тему на основе выбранной начинают
  из «Дом» → «Доступ» → «Вид пульта».
- **Голосом и из «+»** — одна дорога (`POST /api/v1/workshop/make {words, draft?}`; у колонки — то же правило):
  «Сделай виджет: мои дела на сегодня» — черновик своего лица (виджет, навык, игра, тема), карточка «кто просил»
  (`packages-dev/.meta/<id>.json`), агент работает в фоне. Колонка отвечает «Делаю виджет. Скажу, когда будет готово» и
  свободна; в конце сама говорит «Готово…» и около 5 с слушает ответ без «Алиса»: «примерить», «на стол» (ставит
  только пульт, нажатием), «в черновики», «не надо», «переделай: …». Пока агент работает — «Алиса, что с
  виджетом?» и «Алиса, отмени виджет».
- **Карточка черновика** — у каждого черновика в `GET /api/v1/workshop` и `…/drafts/<id>`: `meta` (кто просил — `panel`
  или `voice` и кто именно, слова просьбы, лицо — `widget`, `skill`, `game`, `theme`, стадия — `working`, `ready`,
  `installed`, `parked`, `failed`, `stopped`, последние слова агента), `needs` (настройки манифеста без значений:
  обычные и личные; личная без значения по умолчанию обязательна) и `readyLine` — строка «Готово…», её собирает шлюз
  из манифеста. Событие `workshop.changed` несёт черновик и вид перемены (`made`, `ready`, `failed`, `parked`,
  `installed`, `open:fitting`, `open:consent`…); «В черновики» — `POST …/drafts/<id>/park`. В пульте черновик стоит на
  столе плиткой, «Примерка» — `#/fitting/<id>`.
- **Терминал** — без шлюза:

  ```sh
  duowave plugin new hello --title "Привет"          # или --theme, или --from-openapi api.json
  duowave plugin test hello --phrase "скажи привет маша" --run hello --input '{"name": "Маша"}'
  duowave plugin install hello                       # новая версия в PACKAGES_DIR, выключенной
  ```

- **Claude Code и другие агенты** — MCP-сервер мастерской `POST /mcp/workshop` (токен администратора) с теми же
  инструментами и скилл [`docs/plugins/skill/`](skill/SKILL.md).
- Инструменты включённых плагинов шлюз сам отдаёт как MCP-сервер: `POST /mcp/plugins`, право `plugins.mcp`.

## История

Шлюз хранит историю каждого приложения (план): файлы — по хешу, как в git, одинаковое —
один раз, в `$DATA_DIR/package-history/`.

- **Шаг черновика** — законченный кусок работы: работа агента по одной просьбе (со словами просьбы), сохранение руками
  (сохранения одного человека за 2 минуты — один шаг), возврат, объединение. Шаг пишется, только если файлы
  изменились; правки на диске в обход мастерской становятся шагом «правки руками» перед следующей работой.
- **Версия** — каждая установка: мастерской, из каталога, своя копия. С ней — снимок данных плагина как они были
  перед переменой (`kv`, задачи расписания, картинки; настройки и ключи — нет).
- **Возврат** поставленного: «Только код» (по умолчанию), «Код и данные», «Только данные». История идёт только вперёд:
  возврат — тоже запись, его можно отменить. Версии, которым нужны права, каких нет у работающей, ждут «ок»
  администратора. Встроенные приложения возвращают только данные — их код идёт с версией шлюза.
- **Объединение** двух линий (своя копия и новая версия каталога, правки на колонке и на компьютере): простое — само,
  по файлам, полям манифеста и строкам; спорное, не прошедшее проверку или «через агента» — агент, который при
  неясности спрашивает владельца с вариантами.
- **Место:** колонка — 2 МБ, шаги 30 дней, до 50 на приложение; компьютер — 200 МБ, 90 дней. На диске в `PACKAGES_DIR`
  — работающая версия и одна до неё, остальное — в истории. Колонка может держать историю на компьютере
  («Где хранить историю»).
- **Голосом:** «Алиса, верни погоду как было вчера», «отмени последнее изменение в погоде», «верни список покупок на
  вчера» (переспросит), «верни как было», «что поменялось в погоде?».

API: `GET /api/v1/packages/<id>/history`, `…/history/compare?from=&to=`, `GET|POST /api/v1/packages/<id>/restore`,
`POST /api/v1/workshop/drafts/<id>/restore`, `/api/v1/workshop/drafts/<id>/merge`, `GET /api/v1/history`.

## Другие движки: WASM и MCP

- **`"runtime": "wasm"`** — `backend.wasm` в интерпретаторе wasmi: пишите на любом языке, который собирается в
  WebAssembly. ABI v1, JSON в памяти модуля: модуль экспортирует `memory`, `alloc(len) -> ptr` и функции-обработчики
  `(ptr, len) -> i64` (место ответа `(ptr << 32) | len`, 0 — `null`); шлюз даёт в модуле `host` функции `log`,
  `kv_get`, `kv_set`, `kv_delete`, `fetch`, `settings`, `say`, `call`. Время вызова — «топливо» интерпретатора,
  память — `budget.memoryMb`. Подробно — `gateway/src/plugins/wasm.rs`.
- **`"runtime": "mcp"`** — плагин из MCP-сервера в сети: `"mcp": {"url": "https://…"}` на хосте из прав `net:`,
  настройка `apiKey` (если есть) уходит токеном. Инструменты манифеста — список разрешённых: `handler` — имя
  инструмента на сервере; остальное у сервера «Мозгу» не видно.

## Приложения

Приложение (`"kind": "app"`, `"runtime": "process"`) — своя программа рядом со шлюзом, для нативного кода и чужих
протоколов (Spotify, AirPlay, DLNA). Тот же манифест, права, бюджет и пульт, что у плагина; фразы, инструменты,
источники и события — те же, только вызываются по HTTP.

```json
{
  "kind": "app", "runtime": "process",
  "targets": {
    "linux-aarch64": { "file": "bin/app-aarch64", "sha256": "…" },
    "darwin-arm64":  { "file": "bin/app-darwin",  "sha256": "…" },
    "linux-x86_64":  { "file": "bin/app-x86_64",  "sha256": "…" }
  },
  "health": { "path": "/health", "intervalS": 15 },
  "prefer": "home",
  "budget": { "memoryMb": 30, "storageMb": 15 }
}
```

- **Запуск**: сборка своей платформы, SHA-256 сверяется перед каждым запуском; в окружении — `PORT` (слушать на
  `127.0.0.1`), `DUOWAVE_URL`, `DUOWAVE_APP_TOKEN`, `DUOWAVE_APP_ID`, `DUOWAVE_APP_DATA` (своя папка, переживает
  версии) и `PATH` — больше ничего от шлюза.
- **Шлюз зовёт приложение**: `POST /call/<функция>` с `Authorization: Bearer <токен>` и JSON входа; ответ — JSON,
  как у функции плагина; 404 — нет такой функции. `GET <health.path>` — жив ли.
- **Приложение зовёт шлюз** — Host API по HTTP, только с `127.0.0.1` и со своим токеном:
  `POST /api/v1/apps/host/log`, `GET /api/v1/apps/host/kv`, `GET|PUT|DELETE /api/v1/apps/host/kv/<ключ>`,
  `POST /api/v1/apps/host/say`, `POST /api/v1/apps/host/fetch`, `GET /api/v1/apps/host/settings`,
  `POST /api/v1/apps/host/call/<имя>` — права те же, что у плагина.
- **Свой звук**: приложение отдаёт его по `GET /stream/<имя>`, а в элементе для плеера пишет
  `{"id", "title", "stream": "<имя>"}` — колонка берёт поток у шлюза (`/media/apps/<id>/<имя>`), шлюз пересылает
  его с приложения как есть. Больше ничего с сервера приложения наружу не видно. Проверенно колонка играет MP3 и
  HLS; Ogg/Opus и WAV через плеер колонки ещё не проверены.
- **Надзор**: упало, не отвечает на `health` три раза подряд или трижды подряд вышло за бюджет памяти (RSS) —
  перезапуск через 1, 2, 4, 8, 16 с; пять падений подряд — приложение выключается с причиной в пульте; 10 минут
  без падений — счёт сначала. На Linux `RLIMIT_AS` — восемь бюджетов. Вывод программы — в журнал шлюза и журнал
  пакета.
- **Пример** — `duowave-echo-app` (`gateway/src/bin/echo_app.rs`): только стандартная библиотека, всё перечисленное
  выше. Набросок Spotify — [`apps/spotify.md`](apps/spotify.md).

В каталоге у приложения архив под каждую платформу (`platforms`); нет нашей — приложение серое с причиной.

## Встроенные пакеты

Шлюз несёт в сборке свои пакеты (`packages/`, список и вид — `packages/bundled.json`) и при старте раскладывает их
в `PACKAGES_DIR`; в первый раз они включены. Встроенные навыки шлюза при этом остаются запасными: плагин вернул
`null` или упал — отвечает встроенный.

| Пакет | Что делает |
|---|---|
| `radio` | «включи радио джаз», `radio_search` и `radio_play` для «Мозга», источник радио, карточка в пульте; нерабочие станции помнит неделю |
| `weather` | «какая погода», `weather_now`; Open-Meteo, город из пульта |
| `news` | «новости», `news_headlines`; ленты из пульта |
| `music` | «включи мою музыку», источник `music` из `content/music` |
| `tales` | «включи сказку» из `content/tales`, «сочини сказку» — моделью шлюза |
| `games` | «давай поиграем»: игра идёт разговором через `model` и `continue` |
| `morning` | «утреннее шоу»: погода и новости письмами `app/weather` и `app/news`, потом своя музыка или радио (`app/radio`, `radio_play`) |
| `smart-home` | «включи свет на кухне», `smart_home_status`; письма `system/smart-home` — через подключение Home Assistant шлюза |
| `currency` | «курс доллара», `currency_rates`, карточка курсов ЦБ |
| `shopping` | «добавь молоко в список покупок», `shopping_list`, карточка списка |
| `calendar` | «что у меня сегодня», `calendar_events`, карточка ближайших событий (ссылка iCal — в настройках) |

`PLUGINS_BUNDLED=0` — не раскладывать их, отвечают только встроенные навыки.

## Каталог и пакеты других видов

Из каталога пакет приходит архивом `.vgp` — tar.gz с `manifest.json` и файлами в корне; шлюз сверяет его размер и
SHA-256 с лентой и кладёт в `PACKAGES_DIR/<id>/<версия>/`. Код (плагины и приложения) ставится только из
**подписанной** ленты: рядом с `catalog.json` лежит `catalog.json.minisig`. Ключей у каталога два, оба встроены в
сборку (`gateway/packages.pub`): выпускной и запасной на случай, если первый потерян или утёк, — подпись любым из них
годится; `PACKAGES_PUBKEY` заменяет их (ключ в строке). Без подписи из каталога ставятся только персонажи и темы.
Подписать ленту — `scripts/sign-catalog.sh`. В
ленте у записи — версия API, размещения и `budget.memoryMb`: на колонке не помещающийся пакет серый с причиной.
Обновление оставляет прежнюю версию для отката. Колонка без интернета берёт ленту и архивы через домашний сервер и
проверяет подпись и хеши сама.

**Дополнительные ленты.** Главная лента может назвать до четырёх лент других издателей — необязательное поле
`feeds: [{ "url", "publisher", "title", "verified" }]`, `format` остаётся `1`: адрес по HTTPS, издатель (строчные
латинские буквы, цифры и «-»), название для людей (до 40 знаков, без него — издатель) и признаём ли мы отметки
`verified` её пакетов (по умолчанию нет). Шлюз читает их следом за главной, каждую в свою папку
`packages-catalog/feeds/` со своим ETag; лента, которую главная больше не называет, удаляется вместе с копией. Пакеты
дополнительной ленты идут после пакетов главной, а `id`, который уже есть в ленте раньше, из неё не берётся. Её
архивы и превью — только с её адреса, `publisher` пакета — из её объявления (у пакета главной ленты — его
необязательное поле `publisher`), плагины и приложения из неё не ставятся: подписи для таких лент пока нет. Ленты,
названные в самой дополнительной ленте, не читаются. Выключатель «Не загружать каталог» и `PACKAGES_FEED_URL=off`
выключают все ленты, а колонка через компьютер получает копии их всех.

Тот же формат и та же папка у пакетов без кода: `"kind": "character"` (персонаж) и `"kind": "theme"` (тема).
Персонаж описывается в `contributes.characters` — промт, тоны, аватар, фразы, снимки голоса по моделям, запасной голос
(`docs/plans/characters.md`, раздел 1; примеры — репозиторий каталога `duowave-packages`).
Поле `license` (до 200 знаков) — у пакета любого вида.
