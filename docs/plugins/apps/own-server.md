# VPN — свои серверы для выхода в интернет

Приложение MagicPlace «VPN» (id `own-server`, программа `apps/own-server/`, план —
docs/plans/own-server.md). Человек приносит свои серверы — подписку или ссылки; шлюз
решает, кто куда ходит («Настройки» → «Выход в интернет», `gateway/src/egress`).

## Как устроено

- **Программа** — своя, на Rust, движок [shoes](https://github.com/cfal/shoes) внутри (MIT; часть WireGuard — MPL-2.0).
  Один файл, две роли: управление (HTTP по протоколу приложений) и движок — тот же файл, запущенный с `engine`.
- **Подключения** — подписки и ссылки восьми протоколов: VLESS + Reality (Vision), VLESS + XHTTP, Hysteria 2,
  TUIC v5, Shadowsocks 2022, Trojan, AnyTLS, WireGuard (текст `.conf`). Хранятся в данных приложения
  (`DUOWAVE_APP_DATA/connections.json`, только для него), наружу — никогда: в ответах и журнале только схема и имя
  сервера.
- **На каждое подключение — свой вход** HTTP/SOCKS на `127.0.0.1`. Внутри подписки — «Авто» (самый быстрый сервер,
  проверка раз в 5 минут) или выбор руками; страна выхода — по флагу в имени сервера, иначе спросом через сам сервер.
- **Шлюзу** — письмо `system/network` → `connections` (право `call:system/network`, «да» владельца в «Связях»).

## Функции (`POST /call/<имя>`)

| Функция | Вход | Ответ |
|---|---|---|
| `status` | — | подключения, их серверы: флаг, имя, задержка, «не отвечает» |
| `select` | `{ connection, name \| "auto" }` | выбор руками или «Авто» |
| `check` | `{ connection }` | страна выхода и задержка |
| `refresh` | `{ connection? }` | перечитать подписки |
| `add` | `{ name, source }` | `{ id }` — ссылка, подписка или текст WireGuard |
| `remove`, `rename` | `{ connection, name? }` | |

## Где что работает

`reach.json` каталога и поле `reach` записи приложения (AUTHORING.md, «Откуда приложение работает»). Встроенная копия —
`gateway/src/egress/reach.json`; каталожная, когда новее, главнее.
