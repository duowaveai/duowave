# Пакеты и плагины (`src/plugins/`, `packages/`, `panel/src/shell/`)

Часть описания устройства DuoWave — [ARCHITECTURE.md](../ARCHITECTURE.md). Пути `src/…` — от `gateway/`.

Новое приходит пакетами, ядро не меняется (план, [как написать плагин](../plugins/AUTHORING.md)):
папка `DATA_DIR/packages/<id>/<version>/` с `manifest.json` (`kind`: плагин, приложение, персонаж, тема) и кодом.

- **Хост** (`plugins/controller.rs`): реестр пакетов и включённых (таблицы `packages` и `plugin_kv`), вид пакета
  (системный, встроенный, свой, из каталога); загрузка при первом вызове, выгрузка после простоя, перезагрузка без
  потери прежней версии, откат; `PLUGINS_DISABLED=1` — без плагинов.
- **Движки** за `PluginRuntime`: QuickJS (`rquickjs`, поток на плагин; голос и инструменты ≤ 2 с), WASM (`wasmi`,
  фича `wasm`), MCP-сервер в сети (`mcp_runtime.rs`) и приложения — свои программы под надзором (`src/apps/`:
  хеш сборки, `health`, перезапуск с паузой, память по RSS, Host API по localhost HTTP, свой звук через `/media`).
- **Долгие задачи приложений** (`src/tasks/`, план «Ленты», этап 1): приложение начинает задачу,
  сообщает ход и заканчивает её (Host API `/api/v1/apps/host/tasks…`); шлюз хранит её (таблица `app_tasks`), говорит
  пульту `tasks.changed` и передаёт «Отменить». Перезапуск шлюза и падение приложения — «прервалась», без
  самовосстановления; с настройками на другой компьютер задачи не едут.
- **Host API 2** («Один способ»): права — только хосты интернета (`net:`) и связи шины. Приложение
  даёт фразы и намерения (мост `PluginSkill` → `OwnSkill`, встроенный навык — запасной вариант; ответ — речь, `play`,
  модель шлюза по связи `system/brain`, продолжение разговора), инструменты «Мозга» (`ToolContribution`; ответ
  `{say, play}` сразу действует), источники, события, ритмы, карточки; у него `fetch` к своим хостам, своё `kv`,
  настройки, своя папка и `host.bus` — всё вне приложения письмо шины (`bus::letter`). Управление колонкой
  приложению не отдаётся.
- **Встроенные плагины** (`plugins/bundled.rs`, `packages/`): вшиты в сборку и раскладываются при старте; радио,
  погода, новости, своя музыка, сказки, игры, утреннее шоу, умный дом, курсы, покупки, календарь — на Host API 2,
  виджеты — карточки, своего кода в пульте нет. Их связи даны с установкой. Встроенные навыки остаются запасными, а
  встроенные источники медиа уступают источникам плагинов.
- **Память на колонке** (`plugins/budget.rs`, `operations/system_memory.rs`): бюджет плагинов из живой памяти минус
  запас, у каждого — объявленная доля; под давлением выгрузка, отложенные фоновые вызовы, выключение последнего
  включённого; строки `plugins`, `plugins.apps`, `media.transcode` в реестре «что где доступно».
- **Медиа**: один `MediaSource` для радио, музыки, сказок и источников плагинов; ассеты пакета —
  `/media/packages/<id>/…`, звук приложения — `/media/apps/<id>/…`. Плеер следит за ответами колонки
  (`skills/media/playback.rs`): молчит 5 с — поток идёт через шлюз (`/media/stream/<token>`, AAC → MP3 ffmpeg),
  ответы — в журнал запроса и плагину.
- **Мастерская** (`plugins/workshop/`): черновики `packages-dev`, песочница, агент на «Мозге» со скиллом
  `docs/plugins/skill/`, установка с одобрением администратора, голосовой режим, MCP `/mcp/workshop`, `duowave plugin`.
- **История приложений** (`plugins/history/`, план): объекты по SHA-256, как в git
  (файл, список файлов, запись, снимок данных плагина), метки `draft` / `installed` / `catalog` и лента записей каждого
  приложения в `DATA_DIR/package-history/`. Шаги черновика (работа агента по просьбе, сохранения руками), версии
  (мастерская, каталог, копия) со снимком данных перед переменой; возврат кода, данных или всего вперёд-записью;
  объединение по файлам, полям манифеста и строкам (своё diff3), спорное — агенту, который спрашивает владельца;
  чистка по месту и сроку (настройка `package_history`); колонка шлёт историю компьютеру (`/home/v1/history/…`);
  голосом — правило роутера рядом с фразами плагинов.
- **MIDI-клавиатура** (`src/midi/`, план): шлюз на компьютере (возможность сборки `midi`: midir —
  CoreMIDI, WinMM, ALSA; midly — `.mid`) слышит клавиатуры для приложений с правом `midi`. На Mac — свой поток с
  циклом событий CoreMIDI, иначе воткнутая на ходу клавиатура не видна. Вход открыт для первого слушателя и до 10 с
  после последнего; «владелец» — страница приложения: его ноты отпускаются, когда он уходит; канал нот
  `/api/v1/midi/ws` по билету — в обе стороны, только дома, 15 минут и продление без потерь (`resume`). Ноты не
  попадают ни в журнал, ни в базу, ни бэкенду. SDK пульта — `useMidi`, `useSynth`, `PianoKeys`; в Chromium — запасной
  путь через Web MIDI. Колонка и программа для Linux (musl) — без MIDI.
- **«Колонка + сервер»**: плагин с `prefer: home` зовётся на компьютере по ключу пары (`/home/v1/plugins/…`);
  каталог и архивы колонка берёт через компьютер, если сама не достаёт.
- **API**: `/api/v1/packages` (все виды; включать, выключать, перезагружать, откатывать, копировать —
  `plugins.manage`), `/api/v1/packages/resources`, `/api/v1/packages/themes`, `/api/v1/packages/panel`, события
  `packages.changed`, `plugins.resources`, `workshop.changed`; инструменты плагинов — MCP `/mcp/plugins`
  (`plugins.mcp`). Каталог — подписанная лента (`plugins/catalog.rs`, minisign); главная лента называет до четырёх
  дополнительных (`feeds`): у каждой своя копия в `packages-catalog/feeds/`, их пакеты — после главной, без кода
  (план). Людям каталог показывает **MagicPlace** — встроенный магазин, часть пульта и
  шлюза, а не пакет (`panel/src/magicplace/`, голосом — `talk/store.rs`, событие `magicplace.open`;
  план): поиск на всех языках пакета, витрина, фильтры по виду, лицу, месту и состоянию, свои
  источники в его настройках.
- **Пульт** (`panel/src/shell/`, `panel/src/sdk/`, `panel/src/plugins/loader.ts`): тема — данные (палитры, раскладка,
  плотность, шрифт, скругления), оболочки `TabbarShell` и `SidebarShell`, реестр разделов и слоты с границами
  ошибок; `panel.js` пакетов грузится с шлюза на ходу через import map (её хеш — в CSP), SDK пульта —
  `@duowave/panel-sdk`; `?safe=1` — без плагинов. Контракт темы — `docs/design/glass/THEMES.md`. Карточки
  (`panel/src/cards/`) — виджеты как данные: функция приложения отдаёт детали, пульт рисует. Код пульта любого
  приложения работает только в окошках (`panel/src/frame/`, `/panel/frame.html` со своей политикой: песочница без
  происхождения, `connect-src 'none'`), мост пульта несёт их вызовы, картинки, вопросы и MIDI.

## Как называем и где работает

Решение владельца, 12.11.2026. Слова кода и слова для людей разные — нарочно.

- **В коде, API и справке для авторов** — как есть: **пакет** (единица установки: манифест, версии, права, откат,
  каталог); его виды — плагин, приложение (`kind: app`), персонаж, тема.
- **Людям — в пульте, голосом, в ответах колонки** — **приложение**: всё, что ставится и что можно открыть,
  настроить, убрать, маленькое или большое. У приложения есть лица: виджет (на столе), навык (фразы для колонки),
  окно, расписание. «Дела на сегодня» — одно приложение с виджетом и навыком. Тема и персонаж так и зовутся. Слов
  «плагин» и «пакет» людям не показываем: новые экраны — сразу так, старые подписи пульта меняются в сборке создания
  голосом (план, этап 9).
- **Проект** — то, что не ставится, а делается: видео, сайт, исследование. У проекта файлы и история, агент работает
  над ним по шагам, результат появляется перед человеком; проект может пользоваться приложениями. Проектов пока
  нет — слово оставлено для них.

Размер и место — свойство приложения, а не новое имя. Оно видно человеку («Что ему можно»), облако — янтарём.

| Где работает | Чем | Для чего |
|---|---|---|
| В шлюзе | QuickJS, WASM | Лёгкое; работает и на колонке, в её бюджете памяти |
| Рядом со шлюзом, обычно на компьютере | Приложение `kind: app`, `runtime: process` — своя программа под надзором; программа MCP по stdio из «Подключений» | Своя база, тяжёлый или нативный код, чужие протоколы |
| В сети, в облаке | `runtime: mcp`, серверы MCP из «Подключений» | Чужой сервис; данные уходят из дома |

Метка места в MagicPlace («на компьютере», «на колонке», «в шлюзе», «в сети») — от шлюза, поле `place` каталога и
установленного (`plugins/catalog.rs`, `place_of`). Приложение только для колонки (AirPlay) — «на колонке». Приложение
и для колонки, и для компьютера (`runs: station, pc`, DuoGram) работает там, где его поставили: на шлюзе колонки —
«на колонке», на шлюзе компьютера — «на компьютере»; Турбо дома его не забирает, лицом оно не становится.

Тяжёлые программы пока подключаем через MCP: подключение запускает программу на компьютере (stdio, сборка `pc`) или
ходит к серверу в сети, а его инструменты получает «Мозг». Чего у этого пути пока нет:

- **Лица.** У программы MCP на компьютере нет виджета, окна и «Примерки»: плагину адрес самого компьютера закрыт,
  `runtime: mcp` ходит только к серверу в сети.
- **Долгой работы.** Вызов инструмента ждёт ответа — рендер видео так не дождаться. Нужен приём «начать → узнать, как
  дела».
- **Больших приложений голосом.** Агент мастерской собирает только лёгкие плагины, а своя программа на компьютере —
  готовая сборка под каждую систему. Понадобится движок скриптов на компьютере (Python, Node) с теми же правами и
  бюджетом.

Что продумать по каждому пункту и по проектам — plans/big-apps.md.

Что бы ни сделал агент — приложение любого размера, тему, проект, — оно приходит одним приёмом: плитка на столе,
«Примерка», «да» рукой ([макет](../design/voice-creation/README.md), план).
