# Дом и устройства (`src/home/`, план)

Часть описания устройства DuoWave — [ARCHITECTURE.md](../ARCHITECTURE.md). Пути `src/…` — от `gateway/`.

Один дом — один центр. Центр — шлюз на устройстве, которое не спит (колонка, коробка; компьютер — только пока в доме
он один): он решает, кто отвечает, ведёт разговор и единственный пишет дом — людей, персонажей, «Мозг», ключи,
подключения, комнаты, приложения, память. Остальные устройства — уши (слышат для центра) и Турбо (силы, `src/helpers`).
Людям роли видны метками «Центр» и «Турбо» и значком «слышит»; слово «ухо» — только для схем и кода.

- `devices.rs` — `GET /api/v1/home/devices`: центр, уши, Турбо с ролями и состоянием, событие `home.devices.changed`.
  Компьютер-Турбо и ухо спрашивают центр (ключ пары): своего дома у них нет. Строка дома в пульте, «Настройки → Дом →
  Устройства» и сцена стола читают его.
- `copy.rs`, `queue.rs` — копия дома: устройство, что может ответить само (компьютер-Турбо, ухо), берёт новую ревизию
  центра и применяет без перезапуска (`transfer::import_keeping`, свои ключи доступа остаются), память складывается в
  обе стороны по записи; правки, сделанные без центра, ждут в `home_queue` (миграция 16) и уходят по порядку.
- `ear.rs` — вторая колонка как ухо: её голосовой сокет идёт дальше в центр (`bridge`), без центра — обслуживается на
  месте по копии; правка дома на ухе отклоняется словами (`guard`). «Сделать центром» — центр переезжает по домашней
  сети, без SSH; компьютер-Турбо идёт за ним.
- `rooms.rs` — по комнатам отличаются только режим Алисы, громкость и «Кто отвечает здесь» (`device_rooms`).
- `character.rs`, `telegram.rs` — персонаж с голосом и Telegram — дома: центр называет их Турбо, который озвучивает и
  держит бота (`/home/v1/character`, `/home/v1/messenger/bot`, договор Турбо версии 2).
- `apps.rs` — один список «Установлено» по местам; приложение для компьютера ставится на колонку-центр лицом
  (`Manifest::face_at`: фразы, окно, виджет), а его код — на Турбо по связи (`/home/v1/plugins/install`).
