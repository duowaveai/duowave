# Проверка вручную: где работает шлюз

Как пройти руками всё, что умеет размещение шлюза (план): перенос на колонку и
обратно, колонка с домашним сервером, самостоятельная смена режима, главные настройки и их копии, «Вернуть колонку
Яндексу», журналы. Глазами пользователя: что нажать и что должно получиться. Около 45 минут вместе со сборкой; колонка
перезагрузится 5–6 раз, каждый раз минута без голоса. В конце колонка как до проверки.

⚠️ Это меняет колонку (`quasar.cfg`, программа в `/data/opt`). Нужен root по вики и путь назад — раздел
«[Если что-то не так](#если-что-то-не-так)».

В командах:

- `<проект>` — папка репозитория;
- `<колонка>` — адрес колонки (виден в «Колонках» пульта);
- `<компьютер>` — адрес компьютера со шлюзом в домашней сети (`ipconfig getifaddr en0` на Mac);
- `station` — SSH к колонке: псевдоним в `~/.ssh/config` (`root`, порт 2222) или `root@<колонка> -p 2222`.

## 0. Перед началом

1. **Пульт компьютера открывается** (`http://localhost/panel`), колонка в «Колонках» на связи. Шлюз не запущен —
   ```bash
   cd <проект> && nohup caffeinate -is ./target/release/duowave serve >> logs/duowave.log 2>&1 &
   ```
2. **Распознавание и свой голос на компьютере работают** — они понадобятся в разделе 3:
   ```bash
   curl -s localhost/health | python3 -c 'import json,sys; d=json.load(sys.stdin)["message"]; print(d["speech"]["asr"]); print(d["tts"])'
   ```
   Должно быть: распознавание по адресу `127.0.0.1:…`, голос начинается с `own`. Свой голос медленный (первый звук
   позже 5 с) — колонка его не дождётся: модель голоса могла уйти в своп, сервер голоса перезапустить.
3. **Журнал компьютера** — в отдельной вкладке до конца:
   ```bash
   tail -f <проект>/logs/duowave.log | grep --line-buffered -E "placement|home server|mode:|safety net|settings:|update:"
   ```

## 1. Сборка для колонки (один раз)

Шлюз, собранный из исходников, сборки для колонки в себе не несёт: в «Сменить…» кнопка «Перенести» неактивна. В
выпуске она приходит сама, подписанная ключом выпусков; для проверки — своя, подписанная одноразовым ключом.

```bash
cd <проект>
cargo zigbuild -p duowave --profile station --target aarch64-unknown-linux-musl --no-default-features --features station
COPYFILE_DISABLE=1 tar -czf deploy/station-payload/duowave-station-aarch64.tar.gz -C target/aarch64-unknown-linux-musl/station duowave
cargo tauri signer generate --ci -p "" -w deploy/station-payload/test.key -f
cargo tauri signer sign -f deploy/station-payload/test.key -p "" deploy/station-payload/duowave-station-aarch64.tar.gz
echo "STATION_PAYLOAD_FILE=$PWD/deploy/station-payload/duowave-station-aarch64.tar.gz" >> .env
echo "UPDATE_PUBKEY=$(cat deploy/station-payload/test.key.pub)" >> .env
```

Каждая из двух строк в `.env` — одна (повтор с другим ключом — подпись не сойдётся). Потом перезапуск шлюза:

```bash
pkill -f 'target/release/duowave serve'; sleep 2
cd <проект> && nohup caffeinate -is ./target/release/duowave serve >> logs/duowave.log 2>&1 &
```

## 5. Обновления и страховка — посмотреть

- «У шлюза на колонке последняя версия.», «Обновлять колонку автоматически». «Обновить колонку до …» — когда компьютер
  новее. «Лента выпусков не задана» — так у сборки из исходников, обновлению колонки с компьютера не мешает.
- «Страховка» включена. Сработает — «Страховка сработала…» и «Шлюз на колонке не отвечает · Проверить · Попробовать
  снова».

## 7. Обратно на компьютер

«Сменить…» → «На компьютере» → «Вернуть на компьютер»: последний шаг «Шлюз на колонке остановлен», голос — на шлюзе
компьютера, в шапке нет «шлюз на колонке».

## 8. Уборка

```bash
ssh station '/data/opt/duowave/bin/duowave station remove'
ssh station 'md5sum /system/vendor/quasar/quasar.cfg'      # тот же, что до проверки
cd <проект> && sed -i '' '/^STATION_PAYLOAD_FILE=/d; /^UPDATE_PUBKEY=/d' .env
```

И перезапуск шлюза компьютера. «Вернуть на компьютер» шлюз только останавливает — `remove` убирает программу.

## Журналы и команды

| Что | Команда |
|---|---|
| Шлюз компьютера: где он, режим, колонка | `curl -s localhost/health \| python3 -c 'import json,sys; d=json.load(sys.stdin)["message"]; print(d["panelMode"], d["placement"])'` |
| Ход запросов вживую | `cd <проект> && target/release/duowave journal` (то же — «Журнал» в пульте) |
| Шлюз колонки: голос, запущен ли, домашний сервер | `ssh station '/data/opt/duowave/bin/duowave station status'` |
| Журнал шлюза колонки | `ssh station 'tail -f /data/opt/duowave/gateway/gateway.log'` |
| Шлюз колонки: режим, распознавание, «Мозг» | `curl -s http://<колонка>:8790/health \| python3 -c 'import json,sys; d=json.load(sys.stdin)["message"]; print(d["panelMode"], d["placement"]["placement"], d["speech"]["asr"], d["dialog"])'` |
| Куда идёт голос колонки | `cd <проект> && STATION_SSH=station scripts/station-voice.sh status` |

| Строка журнала | Что значит |
|---|---|
| `placement: …` | Переход, копии настроек колонки |
| `settings: a package … received` | Шлюз получил пакет настроек и перезапустился на нём. Чаще, чем меняют настройки, — ошибка |
| `home server: … is up` / `is away` | Компьютер для колонки на связи или пропал. Ни одной такой строки на «колонке + домашнем сервере» — ошибка |
| `mode: «Свой» → «Шлюз» by itself` / `is back by itself` | Автоматика ушла из «Свой» / вернула его |
| `endOfUtterance … responseSent` без распознавания и ответа | Запрос закрыт пустым — колонка молчит. Ошибка |
| `safety net: …` | Сработала страховка |

## Если что-то не так

- Колонка молчит дольше двух минут после перезагрузки — `STATION_SSH=station scripts/station-voice.sh status`.
- Голос — на шлюз компьютера: `STATION_SSH=station scripts/station-voice.sh gateway <компьютер>` (спросит «y»).
- Колонку Яндексу: `STATION_SSH=station scripts/station-voice.sh yandex`.
- Шлюз выключен страховкой: «Проверить» → «Попробовать снова» или `ssh station '/data/opt/duowave/bin/duowave station retry'`.
- Прежний адрес через шлюз колонки: `ssh station '/data/opt/duowave/bin/duowave station point previous --reboot'`.
- Копии `quasar.cfg` — на колонке в `/data`; исходный файл держите и у себя.

## Найдено этой проверкой (07.11.2026) и исправлено

- **Настройки каждую минуту** (`2a0b0d0`): в версию настроек входили поля, которые шлюз пишет сам (колонку видели,
  вход, ключ использован, провайдер проверен) — компьютер слал пакет каждую минуту, колонка перезапускалась и молчала.
- **«Шлюз» без распознавания молчал** (`caf9567`): запрос закрывался пустым ответом; теперь голос целиком уходит Яндексу.
  В «Своём» к Яндексу не идёт ничего — там соединения с ним нет.
- **Старый домашний сервер в базе колонки** (`8cadf30`): шлюз брал адрес из `.env` только если его в базе не было
  никогда; база, оставшаяся от прежней установки, держала старый. Теперь новый адрес из `.env` побеждает.
- **Окно переноса** (`d246a8f`): заранее говорит, что станет со «Своим»; строка про ключи — над выбором настроек.
