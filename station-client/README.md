# Клиент звонков для колонки

Свой звонок без Яндекса (этап 7 плана интеграции): узел звонков в шлюзе
(`/calls`), а на колонке — клиент, который играет собеседника и отдаёт обработанный микрофон. Код —
свой, по описанию; чужой код не переносим.

## Как устроено

- **Узел звонков** в шлюзе: стороны звонка — страница `/calls` (браузер, WebRTC), телефоны по SIP через
  Asterisk (`deploy/asterisk`) и колонка. Звук внутри узла — 16 кГц
  моно, кадры по 20 мс.
- **Колонка** — без установки программ:
  - `GET /calls/next/<device>` — опрос (`wget`, до 50 с): пока клиент опрашивает, колонка — сторона узла
    (`station:<device>`), ей можно звонить; ответ `call`, как только её звонок принят, иначе `idle`;
  - `GET /calls/listen/<device>?format=ogg` — звук собеседника этого звонка живым потоком Ogg/Opus (16 кГц моно,
    страница на 20 мс) → `decodebin` → `alsasink` (её GStreamer); поток кончается вместе со звонком, и конвейер
    закрывает динамик сам; без `format` — PCM16LE для других клиентов;
  - `POST /calls/release/<device>` — клиент уходит: поток звонка кончается, колонка выходит из узла;
  - микрофон — мост `socat` от звуковой службы колонки (`127.0.0.1:9850`) к порту шлюза
    `CALLS_STATION_MIC_PORT` (9851): шлюз сам подписывается на время разговора и берёт канал `vqe_gain` — тот,
    что берёт звонок Яндекса (16 кГц моно, после эхо- и шумоподавления); оборванный мост (перезапуск шлюза)
    клиент поднимает заново через 5 с, как и опрос; пока шлюза нет, звуковую службу колонки он не трогает;
  - `POST /calls/talk/<device>` — микрофон PCM16LE для других клиентов (chunked).
  Мост микрофона узнаётся по адресу колонки — тому же, с которого идёт опрос.
- **Динамик общий (dmix), поэтому конвейер — только на время разговора** и никогда не убивается: 02.11 конвейер,
  державший динамик между звонками, а потом убитый, оставил колонку без звука для всех, и Алисы тоже, до
  перезагрузки (разбор — в `docs/plans/final-tests.md`, 7.5).
- **Управление — голосом через шлюз**: входящий звонок объявляется голосом Алисы («Вам звонит мама.
  Скажите: Алиса, ответь»), «ответь» и «положи трубку» разбирает маршрутизатор.

`call-client.sh` запускает обе трубы. Эхоподавление — на стороне колонки: VQE вычитает всё, что играет
усилитель (опорный канал — петля с его выхода), и наш звонок тоже; на стороне браузера — его собственное.

## Что на колонке (чтение 02.11, с разрешения владельца)

- **Динамик общий:** ALSA default → `speakers` → `dmix_spk` (dmix, `ipc_perm 0666`) → `hw:0,0`, 48 кГц, 2
  канала. Наш поток смешивается с голосом Алисы и идёт с её громкостью; `mediad` держит устройство только пока
  играет.
- **GStreamer** (`libquasar_gstreamer.so`): по строкам библиотеки — `souphttpsrc`, `souphttpclientsink`,
  `wavparse`, `audioconvert`, `audioresample`, `alsasink`, `oggdemux`, `opusdec`, `fdsrc`. Строки обманывают:
  `audioparse` нашёлся внутри другого имени, а при запуске элемента нет («no such element factory»), как нет и
  `rawaudioparse`. Поэтому звук идёт в Ogg/Opus через `decodebin`, как в рецепте вики.
- `maind` — `/system/vendor/quasar/maind`, не в `PATH`; режим `--gst-launch` есть. Есть `wget`, `socat`,
  `aplay`, `arecord`; нет `curl` и `nc`.
- **Микрофоны** — `multi` поверх `hw:0,1` без `dsnoop`, их держит `maind`: второго захвата не будет.
- В `maind` есть `vqe_gain`, `isLocal`, клиент `AudioClient` к `mediad`; своих unix-сокетов у Quasar нет (IPC —
  TCP на 127.0.0.1).
- **Каналы микрофона по сокету (след):** в `maind` — `SocketAudioSource`, `SocketAudioSourceClient`, сообщения
  `quasar.proto.IOChannelRequest`, `IOAudioChannelsData`, `IOAudioChannelData`; в `quasar.cfg` — сервис
  `yio_audio` на порту 9850 (слушает `127.0.0.1:9850`), каналы `raw_mic_0/1`, `raw_spk_0`, `vqe_0`, `vqe_bnr`,
  звонок Яндекса берёт `vqe_gain`. Схем сообщений в бинарнике нет: формат снимается с живого потока.
- **Протокол 9850 (разбор `maind` на Mac, 02.11):** сервер — `YandexIO::SocketAudioSource`. Кадр — длина uint32
  LE и `QuasarMessage` (как у 9875 в вики): поле 252 — тело (байты), поле 253 — тип. Клиент шлёт тип 159
  (`TYPE_IO_CHANNEL_REQUEST`) с `IOChannelRequest` — шесть необязательных вложенных сообщений: сервер убирает
  клиента из своих групп; поле 6 — отписка, иначе группа по первому из полей 1 → 0, 3 → 1, 4 → 2, 2 → 3. Группе
  3 сервер шлёт тип 158 (`TYPE_IO_AUDIO_CHANNELS_DATA`) — `IOAudioChannelsData` со всеми каналами буфера. Без
  запроса сервер молчит (проверено: 3 с — ноль байт). Подписка на все каналы — 13 байт:
  `09 00 00 00 E2 0F 02 12 00 E8 0F 9F 01`.

## Микрофон: звуковая служба колонки

Колонка звонит сама из канала VQE `vqe_gain` (16 кГц моно, после эхо- и шумоподавления; см.
research/original-alice.md). Второй захват ALSA не
пустят (микрофоны держит `maind`), но канал отдаёт её звуковая служба по сокету (протокол — выше): 02.11 с
разрешения владельца отправлен один запрос подписки — пришли кадры `IOAudioChannelsData` с каналами
`raw_mic_0/1`, `raw_spk_0`, `raw_sync_mic_main`, `vqe_0`, `vqe_bnr`, `vqe_gain` (по 512 отсчётов, 16 кГц, 32 мс;
всего ~230 КБ/с), в `vqe_gain` — звук комнаты. Модуль `LD_PRELOAD` не нужен. Подписка — только на время
разговора; разрыв моста снимает её сам.

## Запуск и откат (⚠️ только с разрешения владельца)

Без установки: скрипт уходит на колонку по stdin SSH, на ней не остаётся ни файла.

```sh
(cat station-client/call-client.sh; cat) | ssh -p 2222 root@192.0.2.23 'GATEWAY=http://192.0.2.10 sh -s'
```

Скрипт работает, пока открыт его stdin. Остановка — Ctrl+C (или закрыть SSH): stdin закрывается, скрипт
прекращает опрос, гасит мост микрофона и просит шлюз отпустить колонку (`release`): идущий звонок кончается, и
конвейер доигрывает и закрывает динамик сам. `maind --gst-launch` не убивать: на это колонка однажды ответила
тишиной до перезагрузки. Пока скрипт работает, колонка — сторона узла
звонков (`station:<device>`).

Прошивку и системные файлы клиент не трогает.

### Автозапуск (⚠️ изменение на колонке — только решением владельца)

Без него клиент живёт, пока открыта SSH-сессия: закрылась вкладка, уснул Mac, перезагрузилась колонка — колонка
молча выпадает из звонков. С ним колонка сама запускает клиент при загрузке; опрос и мост микрофона после обрывов
возвращаются сами. Звонкам Яндекса клиент не нужен и не мешает: у них свой SIP внутри `maind`.

Два файла, как у `S99zdropbear` из вики (страница SSH, шаг 3): скрипт клиента — в `/data/opt/duowave/`,
запуск — `/etc/init.d/S99zduowave` (после `S99quasar` и `S99zdropbear`; адрес шлюза — в нём). Клиент
запускается с `DAEMON=1` и работает до TERM; лог — `/data/opt/duowave/client.log` (две строки на звонок, больше
64 КБ — в `client.log.old`). Корень колонки только для чтения: запись в `/etc/init.d` — между
`mount -o remount,rw /` и `sync; mount -o remount,ro /`.

```sh
# сначала остановить клиент, запущенный по SSH (Ctrl+C), — иначе их будет два
ssh -p 2222 root@192.0.2.23 'mkdir -p /data/opt/duowave && cat > /data/opt/duowave/call-client.sh' < station-client/call-client.sh
ssh -p 2222 root@192.0.2.23 'echo http://192.0.2.10 > /data/opt/duowave/gateway'   # адрес шлюза для клиента
ssh -p 2222 root@192.0.2.23 'mount -o remount,rw / && cat > /etc/init.d/S99zduowave && chmod +x /etc/init.d/S99zduowave; sync; mount -o remount,ro /' < station-client/S99zduowave
ssh -p 2222 root@192.0.2.23 '/etc/init.d/S99zduowave start'
```

Остановка — `/etc/init.d/S99zduowave stop`: клиент отпускает колонку в шлюзе и гасит мост; конвейер идущего
звонка доигрывает сам. Откат целиком:

```sh
ssh -p 2222 root@192.0.2.23 '/etc/init.d/S99zduowave stop; mount -o remount,rw / && rm -f /etc/init.d/S99zduowave; sync; mount -o remount,ro /; rm -rf /data/opt/duowave'
```

Сброс к заводским настройкам очищает `/data`: запуск тогда ничего не делает, пока скрипт не положат снова.
Проверено в контейнере Alpine (тот же `busybox ash`) с заглушками `wget` и `socat`: запуск не держит загрузку,
второй запуск не добавляет клиента, старый pid-файл не мешает, остановка — `release` и ни одного процесса.

## Проверка без колонки

Имитатор колонки — `duowave call-sim` (сборка шлюза для ПК, на том же компьютере): входит в узел звонков, как этот
клиент, отвечает на звонок через `--answer-after` мс (1500 по умолчанию), играет `--play voice.wav` вместо микрофона
(без файла — тон) и пишет услышанное в `--record heard.wav`; `--call "Мама"` звонит сам. Страница `/calls` звонит
ему, как колонке.

## Шлюз на колонке сам по себе

Шлюз может работать на самой колонке (план): сборка для колонки — та же
программа без тяжёлых частей, статическая aarch64 (~12 МБ). Из пульта компьютера это делает переход «Где работает
шлюз» → «На колонке»; руками — команды самой программы на колонке (⚠️ только с разрешения владельца, как всё на
колонке):

```sh
duowave station install [--port 8790] [--home-server http://<компьютер>:<порт> --key <ключ>] [--peer-key <ключ пары>]
duowave station point local --reboot      # голос колонки — к её шлюзу: наша копия quasar.cfg поверх файла прошивки
duowave station status                    # куда идёт голос, служба, программа, место в /data, память, страховка
duowave station point previous --reboot   # голос туда, где был до шлюза (yandex — к Яндексу, <адрес[:порт]> — к шлюзу)
duowave station remove [--keep-data]      # шлюз с колонки (не пока голос идёт в него)
duowave station retry                     # после страховки: запустить снова (голос вернётся к нему после перезагрузки)
duowave station safety on|off
duowave station log [строк]               # конец журнала шлюза
```

- **Что ставится**: программа — `/data/opt/duowave/bin/duowave`, данные и `.env` (порт 8790, VAD по энергии, журнал
  два дня и 10 МБ, без звука) — `/data/opt/duowave/gateway`, служба — `/data/opt/duowave/gateway.sh`, рядом `voice.sh`
  (куда идёт голос). Пульт — `http://<колонка>:8790/panel`. Порт 8790 занят — следующий свободный.
- **Запуск с колонкой**: единственный наш файл на разделе прошивки — `/etc/init.d/S95duowave`, до Алисы
  (`S99quasar`). Он подключает копию `quasar.cfg` (`voice.sh boot`) и запускает службу. Без `/data/opt/duowave` (сброс)
  он ничего не делает. `install` пишет его, только когда запущенный шлюз ответил на `/health`; не ответил за 20 с —
  шлюз остановлен, автозапуска нет.
- **Куда идёт голос**: файл прошивки `quasar.cfg` не меняется. Поверх него подключена наша копия с двумя другими
  адресами (`/data/opt/duowave/voice/quasar.cfg`), только для чтения. При загрузке она подключается, только если файл
  прошивки тот самый, с которого она снята (после обновления прошивки — нет: колонка остаётся обычной Алисой), и если
  адрес в ней наш. Указывает на шлюз этой колонки, а он выключен или удалён — подключается то, куда голос шёл до него
  (`previous.cfg`), или ничего.
- **Служба** (`gateway.sh`) перезапускает шлюз через 5 с. Когда голос колонки идёт в него, при запуске ждёт его
  `/health` до 15 с — Алиса находит его поднятым. В pid-файлах — номер процесса и `boot_id`: номер из прошлой загрузки
  (после отключения питания) не принимается за шлюз, и процесс сверяется по командной строке.
- **Страховка** (выключается `duowave station safety off`):
  - три выхода в первые 30 с за две минуты;
  - или шлюз перестал отвечать на `/health`: две минуты без ответа — перезапуск, третий такой за полчаса.

  Сначала возвращается прежняя версия (после обновления). Потом, если голос колонки идёт в этот шлюз, — отметка
  «выключен» и перезагрузка: при загрузке голос пойдёт туда, где был до шлюза. Шлюз остаётся выключенным до
  `duowave station retry`. Работающий и отвечающий шлюз (без интернета, без компьютера) она не трогает.
- **Голосом**: «Алиса, аварийный возврат к Яндексу» — шлюз отвечает раньше маршрутов и модели и отдаёт колонку
  Яндексу (копия убрана, перезагрузка). «Алиса, переведи шлюз в режим Яндекса» — всё отвечает Яндекс, без перезагрузки.
- **Звук после звонка**: если конвейер звонка кончился ошибкой, клиент звонков пять минут следит за динамиком.
  Динамик «подготовлен, но не играет» 90 с подряд — перезапуск медиа-службы Алисы, 210 с — перезагрузка, не чаще раза
  в час (случай 02.11). `SOUND_GUARD=0` выключает.
- **Домашний сервер**: компьютер со шлюзом даёт колонке распознавание, свой голос и модель, пока на связи
  (`/home/v1` на компьютере, ключ с правом «модели этого компьютера»). В пульте колонки — «Коннекторы» → «Домашний
  сервер».
- **Компьютер и шлюз на колонке, поставленный руками**: «Где работает шлюз» → «Шлюз уже на колонке…» в пульте
  компьютера — адрес колонки и `PEER_KEY` из её `.env`. Компьютер видит его, держит копии его настроек и обновляет его
  без SSH.
- **Откат целиком**: `duowave station point previous --reboot`, затем `duowave station remove`.

## Пакет YAM: шлюз на самой колонке

Для тех, у кого на колонке стоит [YAM 0.2](https://hackalice.me/start/packages/): пакет `duowave/gateway`, пока для
Станции Лайт 2 (`plum`) — файл `duowave-gateway-<версия>-plum.yampkg` в
[выпуске](https://github.com/duowaveai/duowave/releases/latest). В реестре repo.yse.wtf его пока нет: ставится файлом.
Старого `.yap` для `yse` больше нет: реестр yapkg новые пакеты не принимает, YAM 0.1 не поддерживается.

```sh
yam install ./duowave-gateway-<версия>-plum.yampkg   # шлюз запущен и стартует с колонкой; голос колонки пока у Яндекса
```

После установки открыт пульт: `http://<адрес колонки>:8790` (адрес пишет установка). Голос колонки в шлюз — кнопкой в
пульте или `duowave station point local --reboot`; как было — `duowave station point previous --reboot`.

```sh
duowave status                      # куда идёт голос сейчас, шлюз, клиент звонков
duowave gateway start|stop|status   # шлюз на колонке
duowave gateway remove              # выключить: служба убрана, данные остаются, обновления его не включают
duowave gateway install [порт]      # включить снова
duowave station …                   # все команды программы шлюза (duowave station help)
duowave connect 192.0.2.10          # или голос — шлюзу на компьютере: копия quasar.cfg поверх файла прошивки, перезагрузка
duowave restore                     # как было до шлюза
duowave client install 192.0.2.10   # клиент звонков с автозапуском; duowave client remove — убрать
yam install ./duowave-gateway-<новая>-plum.yampkg   # новая версия; шлюз перезапускается сам
```

**Как он запускается.** YAM 0.2 сам сервисы не запускает — только хранит раздел `services:`. Поэтому после установки
и каждого обновления хук `bin/duowave-postinstall` вызывает собственную установку программы:
`gateway station install --managed yam --program /data/yam/share/duowave.gateway/gateway --in-place`. Она пишет те же
файлы, что пульт по SSH: службу `/data/opt/duowave/gateway.sh` с защитой от сбоев, `.env` в `/data/opt/duowave/gateway`,
`gateway-bin` — постоянную ссылку YAM, не папку версии, — и, когда шлюз ответил, скрипт загрузки
`/etc/init.d/S95duowave`. Хук ничего не делает не на колонке (`yam --root` на
компьютере), если шлюз поставлен иначе (пультом — тогда он остаётся, `duowave gateway install` ставит шлюз пакета на
его место) и если шлюз выключен `duowave gateway remove`. Обновляет такой шлюз только YAM (`yam install` файла новой
версии): пульт так и пишет.

**Перед `yam remove duowave/gateway`** лучше вернуть голос (`duowave station point previous --reboot`) и выключить
шлюз (`duowave gateway remove`). Если забыли — колонка не замолчит: у YAM нет шага при удалении, но при загрузке копия,
ведущая голос к шлюзу без программы, не подключается.

Сборка — на компьютере, после сборки программы для колонки (выше) и `yam-publish` из
[репозитория YAM](https://github.com/nyakokitsu/yam):

```sh
YAM_PROFILES=../yam/platforms YAM_PUBLISH=../yam/target/release/yam-publish \
  station-client/yam/build.sh             # dist-station/duowave-gateway-<версия>-plum.yampkg
../yam/target/release/yam --profiles ../yam/platforms --platform plum --root /tmp/duowave-yam install --yes dist-station/duowave-gateway-*-plum.yampkg
../yam/target/release/yam --profiles ../yam/platforms --platform plum --root /tmp/duowave-yam doctor
```

Выпуск (тег `v*`) собирает `.yampkg` и проверяет установку в папку, пакет лежит в черновике релиза. В реестр он
уходит, когда владелец публикует релиз (`.github/workflows/yam-registry.yml`, секреты `YAM_AUTHOR_KEY` и
`YAM_PUBLISH_TOKEN`). Версия в реестре неизменна: ошибка — только следующей версией. Новая колонка в пакете — строка
в `targets` файла `station-client/yam/yam.yaml`; на каждую — свой `.yampkg` с той же программой.
